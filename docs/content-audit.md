## 判断

原站已经有大量正文、交互与 DSH 实现细节。瓶颈不是文章数量，而是**从机制到可证伪主张、从主张到实验、从实验到结论的证据链不完整**。原导航 26 项（含首页），其中 14 项属于 DSH 模块；框架实现细节与 RSI 一般原理的权重失衡。

## 证据范围与未完成事项

本轮精查了与改动直接相关的一手材料。来源台账记录每项到底核对到摘要、元数据、作者文档还是论文特定章节。没有宣称逐条核实整个旧站，也没有独立复现论文性能。

后续按深度优先顺序推进：

1. **真实任务 runner 与一次独立确认实验**：固定模型和环境版本，保存成功与失败的逐题工件、成本、timeout/crash。当前 lab 只分析合成或外部可信观测。
2. **元改进对照**：在相同预算下比较冻结与更新改进器；重复完整搜索，而不是只补测末代。至少包含普通随机/best-of-N 基线与负结果。
3. **DSH 快照可追溯化**：从明确 commit 重新生成包、工具、事件与配置清单；校验全部 API 示例。当前原始快照 commit 未知，不虚构精确性。
4. **原安全专题事实审查**：CoT、metagaming、HF 事件、confessions 等原章尚未完成逐句证据审计；保留来源链接，后续给每个具体数字和事件断言补原文定位。已有文章不因此被视作本轮复现。
5. **训练与开放式搜索深挖**：R5 目前是路线地图，不是 STaR、MAML 或 POET 的完整复现教程。每次只选一个可预算化的问题做深。

## 本轮可复现验证

另加 GitHub Actions 工作流，自动检查生成内容、链接、脚本语法与 lab；页面仍为零运行依赖。

- `python scripts/check_content.py`：生成一致性、章节/路由/来源 ID、本地 HTML 与 Markdown 路径、静态统计 fallback。
- `python -m unittest discover -s tests -v`：完整运行矩阵、缺失/重复/非法观测、成本/约束、保守裁决与选择偏差。
- `python labs/eval_lab.py demo`：五个场景的结果为 keep / inconclusive / reject / reject / reject。
- 已提供待运行的浏览器检查 `scripts/smoke_browser.cjs`：file://、所有课程路由、新实验、正文搜索、手机布局与无 JS 降级。需要本地 Playwright/Chromium；本轮本地缺少 Chromium 且下载超时，因此尚未完成实际浏览器运行与视觉验收。它不是网页运行依赖。
