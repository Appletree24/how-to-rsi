研究来源、版本与结论范围

机制描述、论文实验、公式算例与本地运行记录回答不同的问题。理解一个结论，需要同时知道它来自哪个版本、对应哪段算法或观测，以及哪些条件限制了外推。本章说明站内研究内容的来源层次，并以 DGM 父代选择和合成评测程序为例，区分文献事实、数值推导与实验结果。

机制、实验效果与迁移结论

“DGM 会挑选较少展开的父代”描述机制；“这种选择能在同预算内找到更好代理”涉及实验效果；“它能改善另一个仓库的修复任务”进一步涉及迁移。选择公式可以解释第一层，后两层还依赖对照、预算与目标任务。复合结论需要分层对应来源；只有机制依据时，效用仍属于待检验假设。

DGM 算例：父代抽样概率的来源

R2 的 DGM 算例中，低分父代 B 的抽样概率约为 84%。其规则来自 [dgm] 登记的 arXiv v3 附录 C.2：对可选父代计算 w = sigmoid(10(α−0.5)) / (1+n) 后归一化；α 是表现，n 计仍有代码编辑能力的子代数，可选父代得分小于 1。公式、变量口径与可选集合共同定义了这项计算。

算例中的两个节点由本站构造：A 的 α=0.8、n=9，B 的 α=0.5、n=0，并非作者实测样本。A 权重约 0.0953，B 为 0.5；在只有这两个可选父代时，B 的概率为 0.5 / (0.0953 + 0.5) ≈ 84%。archive 改变会影响归一化分母，把不能编辑代码的子代计入 n 也会改变结果。复算这两个权重只检验公式应用，不包含论文的完整搜索过程。

84% 描述的是 B 在两节点算例中被选中的概率，不是 B 生成更好后代的概率。该算例展示当前得分与展开次数如何共同影响选择；策略是否值得采用，还取决于原文对照与成本设置，以及目标任务上的独立搜索比较。R7 给出了后一类研究设计。

合成评测：keep 裁决的来源

R6 中的成功率 20% → 80%、delta=0.6 和 decision: keep 来自 eval_lab.py 的合成实验，相关入口为 demo_report()、validate() 与 compare()。输入由任务序号构造；比较先验证完整记录，再计算题内配对差、成本与统计门。这些数值解释程序裁决，不代表真实模型观测。

运行结果的核查包括输入生产者、失败与异常记录的完整性、协议参数及计算过程。input_sha256 标识规范化后的 JSON 内容，既非来源签名，也不覆盖命令行参数。相同哈希只说明规范化内容相同，观测来源、写权限和候选事前冻结仍需另外核实；candidate_frozen: true 本身只是输入声明。

站内使用三类标记区分证据：“来源报告”指作者在指定设置下报告的结果；“本站算例”指解释公式或构造反例的数值；“本仓库运行”指可定位代码与输入的执行记录。解析器自应用实验与 合成数据评测属于最后一类，均用于说明局部机制，不涉及真实模型调用。

版本定位与变更影响

正文中的 [stop]、[dgm] 等标识链接到来源，下表同名条目记录版本与阅读位置。arXiv 版本号和源码 commit 定位本文讨论的材料，不表示它们是最新版本。checked_at 是核对日期，与论文发布日期及阅读覆盖范围分别记录。只登记在线快照的文档，其内容没有被固定到永久不变的 commit。

来源版本变化时，公式、变量定义、实验预算和文字表述可能分别发生变化。依赖旧定义的推导，需要保留旧版定位，并依据新版差异决定是否重算。单独替换链接会让旧数字失去出处；混用新正文、旧代码与其他配置的运行，也会破坏版本对应关系。缺少旧文或差异记录时，依赖该对应关系的精确结论仍无法核实。
