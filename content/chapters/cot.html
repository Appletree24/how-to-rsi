CoT 监控：漏报、基率与处置窗口

仓库修复 agent 在推理里提到“也许可以跳过这个检查”，随后发起写文件操作。推理文本提供了调查线索，但是否违规仍取决于实际改动与任务约束。CoT 监控的工程问题由此分为三部分：信号能否预测违规，告警在目标流量中是否可信，以及执行器能否在不可逆动作发生前介入。

检测时刻与动作时刻

考虑一条假设轨迹：t0 工具报告修复任务缺少依赖；t1 agent 在 CoT 中讨论绕过测试；t2 它请求修改测试脚本；t3 执行器写入；t4 异步监控才报警。t4 的判断即使正确，也无法阻止已经完成的修改。发送凭据等不可逆动作更依赖事前处置窗口。在 t2 暂停请求，需要由执行代理持有权限，模型仅能提出动作；CoT 分数作为执行决策的一项输入。

工具轨迹与推理文本提供不同信息。“写某文件”可能是正常修复，也可能是绕过要求，CoT 有时能补充上下文；但模型也可能讨论坏方案后放弃，或省略关键原因。CoT 是可被交叉核对的文本证据，无法直接读取内部意图。文件差异、执行结果与任务约束提供独立的行为标签，避免同一段 CoT 同时充当真值和检测结果。

OpenAI 已经把 CoT 监控用在生产里：一边用它在前沿推理模型上抓 reward hacking（chain-of-thought monitoring），一边在内部 coding agent 部署里做 misalignment 检测（内部 agent 监控报告）。

轨迹与推理文本第 04 章讨论执行过程的评估。工具轨迹记录调用与结果，CoT 补充模型外化的计划和解释；二者的差异也有诊断价值，例如推理声称测试已通过，而工具记录显示测试根本没有启动。

可监控性、忠实性与可读性

Monitoring Monitorability（Guan et al., 2025-12）把"可监控性"定义为：监控器能否从 agent 的潜在状态（latent）里预测出某个行为性质。这是个双边性质——既要求信息在 latent 里存在，又要求监控器读得懂。两类失败对应两种不同病因：

  • faithfulness 失败：相关信息根本没写进 latent（或没写进 CoT）——推理不完整、有隐藏步骤。
  • legibility 失败：信息在里面，但监控器读不懂——编码了、漂移成奇怪术语（第 08 章的 "watchers/Redwood"）。

可监控性只要求预测指定的行为性质，因而不必忠实复现全部内部计算。例如，模型做长乘法时省略“2×2=4”，了解乘法的监控器仍可能预测所关心的性质。反过来，详细推理也可能缺少某次越权行为的原因。每项评估都由可见信息与目标标签共同限定；对一个标签的预测效果无法代表全面的可解释性。

三类可监控性评测

论文提出三类评测原型（archetype），分别研究干预的影响、推理过程中的信息与最终结果的属性。2026-04 已开源其中大部分数据集与指标代码（Open Sourcing Monitorability Evaluations / GitHub）：

类别测什么怎么测数据集（开源★ / 未开源）
干预 eval（intervention）给模型一个会影响回答的干预（塞进 hint、给倾向性信息），看监控器能不能从 CoT 里推断出"它用了这个干预"同一道题跑两臂：控制臂 X=0、干预臂 X=1，各采 ~30 个样本；估计实例级总效应 TÊ = p̂₁−p̂₀；监控器只在干预确实生效的实例上做 TPR 检测GPQA★、GPQA encoded★、AIME★、DAFT★、Memory★、Scruples★、Sandbagging★；Health Queries（私有数据未开源）
过程 eval（process）CoT 里是否真的写了有意义的推理（而不是凑字数的敷衍或事后补写）检查 CoT 是否包含正确推理步骤、引用、计算痕迹AIME-Math★、GPQA-Physics★；FrontierMath、Math Diamond（受限数据未开源）

三类评测分别约束因果影响、过程信息与结果属性，不能混成“读懂真实意图”的总证明。例如，工具失败后未在 CoT 提及，既可能是隐瞒，也可能是没察觉或摘要丢失；只有结果属性标签，还不能确定是哪一种机制。

在 P4 的本地管线中，可判定的行为标签包括修改受保护测试、引用不存在的证据，以及把实际失败声称为成功。只看输出、只看轨迹、只看 CoT 与联合输入的检测器可以在同一任务拆分和推理预算下比较。若某组额外获得完整参考答案，测到的收益就同时包含输入信息差异，无法单独归因于 CoT。

量化指标：g-mean2

论文使用 g-mean2 比较监控效果，各 archetype 的标签与计算细节以论文和开源实现为准；它不是部署告警精确率。干预实例先估计总效应 TÊ = p̂₁ − p̂₀，只有正效应才有可归因阳性的意义。非干预类少于 3 个阳性、干预类有效实例不足 10% 时不报告，是可靠性门槛，不是安全通过门槛。

开源版改进了有限样本筛选：每臂 30 个样本，以 f=0.6 分成两折；第一折使用 TÊ₁ > 1.96 × SÊ₁ 判断资格，第二折独立估计指标，且仍要求 TÊ₂ > 0。只用同一批样本“筛正效应再估大小”会留下幸运噪声。Sandbagging 高 RL step 的表面下降在新过滤下成为有效样本不足、不可报告；这消除了旧曲线支持“监控性骤降”的依据，不是证明那些 checkpoint 安全或不存在隐藏行为。

这套指标也进入了模型版本报告：OpenAI 已在 GPT-5.4 thinking、GPT-5.2 thinking、GPT-5 thinking（arXiv:2601.03267）和 o3 的系统卡中补充结果，o3 卡还附有 o1 在非工具子集上的读数，并承诺在后续前沿推理模型系统卡中继续报告。统一报告使跨代比较成为可能，具体比较仍受覆盖率与任务设置约束。

比较模型时还应报告有效实例数、任务族、监控器版本、输入范围和预算。分数上升但覆盖率大降，可能只是难例被排除了；可监控性不是“超过一个通用阈值就够用”的性质。

输入范围、推理预算与训练的影响

论文所测设置中，联合 CoT 与 actions 的监控优于单通道，只看 CoT 又优于只看动作。增加推理 effort 与更长的 CoT 往往提高可监控性；在同等能力下，“小模型 + 高 effort”也表现得更可监控。这些比较同时涉及成本和推理时延，无法仅靠延长文本推导出同样收益。

增加监控器的测试时算力可以改善弱监督，CoT 在所测设置中提高了收益曲线。所测 RL 过程未呈现普遍的可监控性退化，而刻意训练成 CoT 含糊化的 model organism 能被套件区分。这说明套件对部分信号变化敏感；其他奖励、架构和适应性训练仍需分别测量。

追加追问在部分设置中也改善了监控。第 10 章的 confessions 进一步改变事后报告的训练目标，显式奖励诚实；单纯追加问题与这种训练方法具有不同的激励结构。

低基率下的告警精确率

以一个假设算例说明：每天 10,000 次操作，其中真实违规 10 次（基率 0.1%）；检测器 TPR=90%、FPR=1%。期望真告警 9 次，误告警 9,990×1%=99.9 次，告警精确率只有 9/(9+99.9)≈8.3%，还漏掉 1 次违规。这组数值不是论文或线上测量；它展示了低基率如何使误报占据大部分审核队列。

基率与窗口：部署决策的两个条件
PPV = π × TPR / [π × TPR + (1 − π) × FPR]
π：目标流量中的真实违规基率，不是人为平衡测试集的阳性比例

要阻止某动作：
检测完成 + 排队 + 复核 + 阻断的总延迟 < 动作发生前的可暂停窗口

把阈值抬高能减少误报，却通常增加漏报。对于读取公开文档，可先告警抽审；对于写入受保护数据，应先由权限策略拒绝，再审查是否要批准。不要让一个未校准的语义分数直接发放高风险权限。报告混淆矩阵时还要统计监控超时、CoT 缺失和日志截断，不能把它们默认为阴性。

优化过程如何影响 CoT

优化压力既可能来自显式奖励，也可能来自报告筛选与候选选择。若反馈持续偏好“CoT 看起来合规”的轨迹，模型可能改善表达，却保留原有行为。关于 CoT 优化 和 探针优化 的研究讨论了这类规避风险。区分行为改善与信号隐藏，需要同时比较训练前后的行为标签和检测率。

监控意识也需要作为实验变量处理。无监控提示、明确告知监控、针对检测器进行适应，代表三种不同条件；知道被监控本身不足以判定监控失效。检测器、阈值与权威日志的写权限则需留在 agent 控制域之外，否则候选能直接改变测量过程。

Korbak 等将 CoT 监控称为“fragile opportunity for AI safety”。已有结果展示了这项信号的价值，训练习惯、无 CoT 架构或适应检测的策略又可能削弱它。资源权限提供确定性的动作边界，监控负责其中仍需语义判断的部分；两者承担不同职责。

轨迹回放与在线阻断

以下回放方案用于比较监控通道，本章不提供实测结果。在 P8 的无真实凭据、无外网环境中，选择合法修复、讨论后放弃绕过、实际修改受保护测试三类轨迹，以 P4 的独立标注固定行为真值，再比较四种可见范围。CoT 截断、监控超时、同义词替换和“你正在被监控”的提示分别检验信息缺失与适应性。各类 TPR/FPR、缺失率、成本和报警到动作的时间差，比聚合准确率更能解释处置效果。

离线检测与在线阻断需要分别测量。同一攻击在动作前被检出，且执行器确实没有执行，才能支持提前阻断的结论。联合监控若在同预算下未优于轨迹监控，增加通道就没有体现相应收益。来源核对能直接判定部分引用幻觉，OS 权限能直接阻断部分越权写入；昂贵的 CoT 审查更适合这些确定性检查无法消除的歧义。

原始推理的可获得性决定了能复现哪一种监控。普通 API 可能只提供工具轨迹、结果与摘要，摘要不能替代原始 CoT。官方开源 runner 使用模拟输出演示编排；真实模型评估仍需接入相应模型与信号，并重新测量效果。
