任务数据的独立性、可回答性与权限

把 checkout 的一张工单用于调提示词，另一张改写后放进测试集，即使任务 ID 不同，也可能仍在测试同一条已记住的规则。与此同时，参考答案与文档都在一个 JSON 文件里：程序没有传答案，不代表拥有 shell 的 Agent 读不到。数据独立性、任务可回答性与访问权限分别约束了分数的解释、答案的依据和材料的可达范围。

可回答性与参考答案

知识助手需要在指定环境、时点与权限下给出处置依据。tasks.json 的 checkout-0 将三种信息分开：故障事实说明发生了什么，当前手册规定动作适用条件，工单中的建议则是待核实信息。人工 oracle 也必须能只依靠 Agent 获准看到的材料完成任务；否则参考答案包含了输入中缺失的前提。

当前手册缺失时，原任务的证据要求已无法满足，可接受输出应包括拒答或补充信息请求。若另一份手册提供同样有效的依据，评分器也需认可这条替代路径。参考答案因此包含动作与允许的证据组合；只固定一个任意文档 ID 会把正确答案判错。

同一记录，三个消费者

学习夹具把工单、环境与参考答案放在一个文件，便于检查。run_agent 只接收 prompt 与 documents；grade 在循环结束后读取 expected_answer、required_citations 与 forbidden_answers；runner 读取 family/split 来组织实验。不能把整个 task 对象直接序列化进模型上下文。

核心契约 · 具体实例见数据文件
{
  "id": "checkout-0", "family": "checkout", "split": "dev",
  "prompt": "Diagnose incident_id=checkout-incident-0 ...",
  "documents": [{"id":"checkout-runbook","title":"checkout current runbook","body":"..."}],
  "expected_answer": "resize_pool",
  "required_citations": ["checkout-incident-0", "checkout-runbook"]
}

这是示意记录，不是完整任务；省略号不应作为实验输入。参数分离不是安全隔离：目前无 shell 的工具分发器限定了可达操作，但若将来给 Agent 文件读取或代码执行，同一主机上的答案文件、挂载路径、进程环境和日志都会成为潜在泄漏面。P8 才讨论隔离执行；不能靠 system prompt 写“不要读答案”代替它。

权限、相关性与答案保密不能用一个过滤器解决

边界必须回答的问题改变条件后的反例
用户资料权限该租户、角色此刻能否读取这份文档及其摘要？同 query 命中高权限缓存，隐藏引用后正文仍泄密；P3 再授权整个派生答案
任务可用材料该修订适用于部署版本和事件时点吗？用户有权读旧手册，但旧手册不是当前操作依据；权限正确不等于答案正确
评测秘密答案、隐藏测试、确认集反馈是否只能由裁判读取？不传 expected_answer，却把评分错误中的标准答案写入下轮 memory，仍污染评测
公开发布来源、许可与脱敏是否允许发布整份任务和附件？删除姓名但保留可关联的内部路径、客户日志或密钥，仍不能公开

知识助手需以文档版本与 ACL 为核心；仓库修复需区分公开仓库、任务环境与私有验证器；评测平台需隔离任务作者、被测策略和确认集审计权限。可共用任务 ID 与来源记录，但不强行用 documents 数组表示全部环境。当前 starter 没有认证、ACL 服务或隐藏测试存储，以上是扩展契约。

分组拆分与泛化目标

任务 ID 标识样本，family 标识可能共享答案模板或环境的相关样本。checkout 的两张工单不能一张进开发、一张进确认。公开示例按服务家族拆成 dev 与 test_public；后者已公开，不能再叫盲测集。load_dataset 会检查重复任务 ID、已知 split、family 跨 split、重复文档 ID、required_citations 是否存在与空数据集，但不会自动识别语义重复或预训练污染。

手算反例：假设 40 张工单来自 4 个故障模板，每个模板改写 10 次；这是教学假设，不是本仓库样本统计。按行随机分成 20/20，很可能每个模板都出现在两边。策略只记住“某模板→某动作”也能答好确认题，40 条记录并不等于 40 份独立证据。按模板分组拆分后，测的是迁移到未见机制；按服务分组测跨服务，按时间切分测后续事件，三者不是同一个泛化问题。

分组也不是越粗越好：若目标是同一服务下的新事故，把全部服务互斥会改变目标分布。应先写清上线问题，再选分组键；遇到同一补丁派生多题、同源文档、生成器模板等跨组关系，应检查连通的来源簇，不能只信一个人工 family 标签。置信区间在对应家族或仓库层聚类，组太少就明确报告不确定性。

污染沿着反馈回路进入，不只从答案字段进入

直接泄漏发生在 prompt、工具观察、文件挂载或异常信息包含参考答案时。各消费者的实际输入快照和答案路径可达性，是检查这类问题的依据。近重复泄漏更隐蔽：改 ID、换服务名或同义改写没有改变解题机制。来源关系与跨组近重复审计需要同时保留，相似度阈值本身无法证明独立性。

选择泄漏发生在反复根据 test_public 分数调整策略时。此时测试集已成为开发反馈，重新命名或更换随机种子不能恢复盲测。记忆泄漏则把确认题失败和正确答案写入长期 memory，使下一轮相同任务失去独立性。P3 的记忆快照、P9–P10 的反馈权限都用于限制这条回路。

生成数据可以扩充开发分布，也会放大同一个生成器的格式与标签偏差。如果模型只学会这些暗示，增加样本量会让有偏结论显得更稳定。一个小规模扩展可从人工解答三题、构造应失败的 mutant 开始，再生成和独立审计；20–40 题适合作为初始实验规模，但不代表统计充分。

实验身份与续跑

同一配置自动续跑；保存 stdout 的 run ID
python -m projects.repoops.runner run --policy evidence --limit 2
python -m projects.repoops.runner run --policy evidence
python -m projects.repoops.runner report RUN_ID
python -m projects.repoops.runner run --policy evidence --split test_public

将 RUN_ID 换为打印的 64 位值。前两条配置的 ID 应一致：limit 只是本次执行多少条，不改变目标任务；已落库 trial 不再运行。manifest 绑定数据 hash、split、任务清单、repeats、policy、模型与声明的修订、system prompt、max_steps、timeout，以及 agent.py/runner.py 的内容 hash。它不自动记录整个操作系统、模型二进制或远端服务版本；记录一个 digest 字符串不等于实际校验加载权重。

数据、上述代码、prompt、模型声明或预算变化会产生新 ID。哈希证明“这些输入是否相同”，不证明“输入正确、未污染、获授权”。报告 complete=false 时只用于调试；只展示先完成的简单题会产生选择偏差。repeats 变化是新实验，重复采样不是增加独立任务数。

数据校验与污染审计实验

现有 loader 之外，还可增加 prompt 类型、文档长度、答案枚举与空 split 检查，并将错误定位到 task_id。这里讨论的是尚未实现的扩展；现有通用错误信息不提供这样的定位能力。这些检查能提前拒绝格式错误，任务是否可答、证据是否充分仍需语义审计。

六类任务变化

数据扩展实验可分别构造规则冲突、缺失证据、误导评论、无关结果、工具超时和多个正确处置六类任务。每题记录人工 oracle、一个应失败 mutant、允许资料与严重错误；其中工具超时由执行夹具触发，单在文档中描述超时不会测试执行边界。选取 5 题由两人独立标注，保留证据不足、题意歧义和评分器过窄造成的分歧与裁决。

任务卡同时记录来源、许可、脱敏、分组依据、版本和排除项。将同 family 放入两个 split，应被 loader 拒绝；跨 family 的同义改写可能通过 loader，需要来源审计发现。最后比较只改 limit 与改 prompt 的运行：前者保留实验身份，后者产生新身份。输入快照、拆分清单和错误记录共同保留这些判断的依据。
