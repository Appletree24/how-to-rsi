RepoOps Lab / P5 · 第 5–6 周 · 前置：事务、HTTP、并发与取消

队列、租约与故障恢复

worker 失联后，任务被重新领取；旧 worker 又在稍后提交结果，哪一份应该生效？从这个问题出发，将本地 runner 扩展为带租约、fencing 和幂等提交的调度服务。

本地 runner 的事务范围

现有 runner 在每个 trial 外持有 SQLite 写事务，结果与轨迹一起原子提交；已提交任务以复合主键去重。进程崩溃时未提交事务回滚，下次重跑该任务。它适合单机串行学习，不适合长时间持锁的多 worker 服务；外部调用完成后、本地提交前崩溃会再次调用，因此不具备外部副作用 exactly-once。报告可以缓存，计费不能因结果未保存而假装没发生。

控制面与 worker

Go 控制面接收实验规格，数据库持久化 experiment/trial/attempt，Python worker 调用模型和环境，artifact store 保存大轨迹，评分 worker 产生独立评价。MVP 先使用一个关系数据库和轮询队列，等测出数据库争用再引入消息中间件。研究平台岗位强调的是可靠性与可扩展性的取舍，技术栈数量不能替代这一能力。

接口语义必须验证
POST /experiments按 Idempotency-Key 创建实验同 key 同规格返回旧 ID；同 key 不同规格返回冲突
POST /trials/claim原子领取到期可运行任务返回 attempt_id、lease_until、fencing_token
POST /attempts/{id}/heartbeat续租仍属于当前 worker 的执行旧 token 不得续租；取消状态不得复活
POST /attempts/{id}/complete提交 artifact hash 和结果token 与状态一致才接受；重复相同提交幂等
POST /experiments/{id}/cancel停止排队并请求取消运行区分取消请求、worker 已终止、费用结算完成

领取任务、续租与提交

  1. 先写 experiment 不可变规格：任务集、候选、模型/采样参数、环境/评分器、每题预算和总预算；保存内容哈希。实验启动后不能原地改参数。
  2. 把 trial 与 attempt 分表：一个 trial 是预定的 task×repeat×arm；一个 attempt 是基础设施重试。模型自身的第二次解题若被当作 pass@k，就不能同时伪装为免费重试。
  3. 在短事务内领取任务、递增 fencing_token、写租约，随后提交事务，再做慢调用。完成时执行条件更新；旧 worker 的结果可入诊断日志，但不能覆盖新结果。
  4. 给任务状态制定合法转移：queued→running→succeeded/failed/cancelled；租约失效可重新排队，但历史 attempt 永远保留。采用数据库时间，避免 worker 时钟不一致。
  5. 模型限流按 provider/model 共享额度；退避加入 jitter，限制次数和总 deadline。Go 的 context 取消要传递到 HTTP 客户端、worker 与环境销毁。
  6. 大轨迹先写临时对象，计算 hash，再以事务提交引用；定期清理孤儿对象。不要让数据库结果指向尚未上传完的文件。
课程设计 · PostgreSQL 风格的完成提交核心，不是完整服务
UPDATE trials
SET state = 'succeeded', result_uri = :uri
WHERE id = :trial_id AND state = 'running'
  AND fencing_token = :token
  AND lease_until > CURRENT_TIMESTAMP;
-- 更新 0 行：当前 attempt 无权完成，不能重试成无条件覆盖。
-- 同一个事务写 attempt 终态；幂等重复提交需校验原结果 hash。

租约解决调度所有权，fencing 解决过期持有者写回；它们不能自动撤回外部 API 的副作用。真实处置动作使用下游幂等键或先查询状态；无法确认结果时进入人工/补偿流程。个人项目先让 Agent 输出 patch，不自动执行运维动作。

重复投递与迟到提交

用一个本地假模型服务模拟 429、超时和迟到响应，先用 2 个 worker：领取后终止一个进程；等待租约过期；让另一进程完成；再提交旧 token，必须被拒绝。随后重复提交同一实验 10 次，只应得到一个逻辑实验。对取消后迟到结果、对象上传失败、数据库暂不可用分别写复盘。

负载报告记录机器配置、并发、任务时长分布、吞吐、排队时间、数据库争用和失败数。先用 100 个假任务观察排队和争用，再增加负载。核对有无任务丢失、旧结果覆盖和未记录的失败。

练习：实现可取消的 worker pool

用 Go 写一个有界 worker pool。取消 context 后，检查所有 goroutine 是否退出；使用竞态检测，并记录取消前后的 goroutine 数量。保留接口说明、状态表和故障日志，再写下数据库队列的适用规模与更换条件。
