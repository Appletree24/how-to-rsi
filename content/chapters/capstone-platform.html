RepoOps / P5 · 调度与恢复

租约、重试与外部费用的一致性边界

worker 失联后任务被重新领取，旧 worker 仍可能稍后提交结果。拒绝这份迟到结果能保护数据库，却无法撤销它已经发生的推理费用。本章用 SQLite 故障时序拆开三个问题：哪个 attempt 持有执行权，哪份结果被接受，以及外部副作用如何记录和去重。

机制与来源范围

通信异常、限流和连续任务的执行正确性，也是公开 Agent 项目讨论中的常见主题。卡码的公开转载记录了这些话题及候选人对后端基础的强调；这里采用的是 2026-09-20 可见的转载材料，付费原帖未核对，个人面试自述也未经企业确认。下文租约、fencing、幂等和取消的分析来自项目机制推演，不以转载中的技术回答为原理依据。

具体依据包括本章 SQL、独立实验源码，以及 SQLite 事务文档 §2.1–2.3、Stripe 幂等请求契约和 Go 1.26 context 源码中的 CancelFunc 说明。后两者分别用于说明特定下游服务的幂等行为和取消信号语义，不能推广为所有模型服务的保证。

本地 runner 的事务范围

现有 runner 在每个 trial 外持有 SQLite 写事务，结果与轨迹一起原子提交；已提交任务以复合主键去重。进程崩溃时未提交事务回滚，下次重跑该任务。它适合单机串行学习，不适合长时间持锁的多 worker 服务；外部调用完成后、本地提交前崩溃会再次调用，因此不具备外部副作用 exactly-once。报告可以缓存，计费不能因结果未保存而假装没发生。

三个项目，三种需要恢复的对象

恢复对象决定了 worker 服务需要保存的状态。知识助手的单次只读回答可由用户重试；仓库修复还涉及工作目录、构建进程与未发布补丁；评测平台需要保留每个研究条件的失败和成本。它们共用所有权机制，但副作用的处理各不相同。

项目需求逻辑结果与 attempt 产物恢复后仍存在的事实
知识助手在时限内给建议请求结果绑定证据版本与权限；每次 attempt 独立记录模型调用丢失答案不代表没付推理费用；重试也必须重新确认响应权限
仓库修复提交可审查 patch固定 commit 上的 diff 与验证 artifact；attempt 独立工作目录拒绝旧结果不自动终止旧进程或清理文件；禁止多个 attempt 写同一工作树
评测平台提供公平对照trial 固定 task×repeat×arm；attempt 记录基础设施执行历史更多采样消耗研究预算；不能把较差解答改称网络重试后丢掉

单机串行 runner 已能恢复尚未提交的 trial。多人并发、长任务恢复或远程取消，则要求将慢调用移出数据库事务，改用短事务领取和提交。消息队列改善唤醒与积压管理，结果发布权仍需由持久状态判定，任务正确性仍由评分器判断。

控制面与 worker

服务化设计可以由 Go 控制面接收实验规格，数据库持久化 experiment/trial/attempt，Python worker 调用模型和环境，artifact store 保存大轨迹，独立评分 worker 产生评价。关系数据库加轮询队列足以表达这些责任；消息中间件是否必要，取决于数据库争用等实际瓶颈。研究平台的可靠性与可扩展性要求，也体现在这类取舍中。

上述服务尚未实现。本章代码仅包含一个标准库 Python、单进程、显式逻辑时刻的机制实验，独立于现有 runner，不启动 Go 服务，也不测真实并发、模型能力或吞吐。以下接口表用于定义目标服务契约。

接口语义必须验证
POST /experiments按 Idempotency-Key 创建实验同 key 同规格返回旧 ID；同 key 不同规格返回冲突
POST /trials/claim原子领取到期可运行任务返回 attempt_id、lease_until、fencing_token
POST /attempts/{id}/heartbeat续租仍有效且属于当前 worker 的执行旧 token、已到期租约、取消状态均不得复活
POST /attempts/{id}/complete提交 artifact hash 和结果token 与状态一致才接受；重复相同提交幂等
POST /experiments/{id}/cancel停止排队并请求取消运行区分取消请求、worker 已终止、费用结算完成

Trial、attempt 与执行所有权

锁或租约决定调度器当前把任务交给谁，但无法强制失联进程停止。W1 卡在网络请求期间租约可能过期；W2 接手后，W1 的旧请求仍可能成功。结果数据库可以保证一个 trial 最多接受一个终态结果，同时允许故障恢复造成重复计算。不可逆外部动作则需要下游协议提供额外约束。

trial 固定为 experiment 下的 task×repeat×arm；attempt 是为完成这个 trial 发起的一次基础设施执行。规范、模型与采样参数、环境与评分器版本、每题和总预算共同进入不可变实验规格及其 hash。更换模型、提示词或增加采样，属于新的研究条件或采样记录，不能包装成免费基础设施重试后继续报告 pass@1。失败 attempt 及其成本也保留在历史中。

状态 / 所有权不变量具体约束破坏后会发生什么
一个当前持有者trial 的 token 由数据库在领取事务中递增；attempt 以 (trial_id, token) 唯一，worker 不能自报更大 token若 token 复用，旧进程可冒充新 attempt；token 也不是身份认证凭证
只能在有效租期写入新增完成必须同时满足 state=running、token 相等、lease_until>now只验 token 会接受已到期但尚未重新领取的提交；只验租期会误用新 worker 的租期
终态不可改写succeeded / failed / cancelled 不再回到 running；同一次成功的重复提交只读取旧结果取消后复活，或者晚到结果覆盖已经发布的评价
重新领取不抹除历史running(token=n, expired) → running(token=n+1)；旧 attempt 标 expired，新 attempt 标 running，同事务提交覆盖同一条 attempt 会把旧费用与故障证据擦掉

完整服务的状态可为 queued → running → succeeded / failed / cancelled。可重试的基础设施错误先结束 attempt，再按预算决定是否重新排队，failed 表示不再重试。实验脚本只实现 queued、running、succeeded、cancelled 和 attempt 的 expired；到期重领直接将旧 running 换成新 running，不依赖清理线程先行处理。失败分类与预算调度不在该脚本范围内。

平台的 succeeded 表示接受了一份完成结果，其内容仍可能是错误答案；P4 的 passed 则是特定版本评分器对任务的判断。生成完成、评分完成和研究条件可比较是不同事实。目标服务保存原始 artifact 与独立评分版本，judge 暂不可用时只重跑评分，避免重新调用模型改变样本。机制实验只存结果字符串，尚未实现这条管线。

在写入边界检查 fencing token

token 必须在资源接受写入的同一原子操作中比较；worker 本地检查无法阻止检查之后失去租约。下面是实验的条件更新核心，外部慢调用位于短事务之外。SQLite 的 BEGIN IMMEDIATE 提前获取写事务，将读取、条件更新和 attempt 状态变更合成一个原子过程；同一时刻只允许一个写事务，因此这里不涉及多机吞吐保证。

实验实际使用的 SQLite 语义 · now 为显式逻辑时刻
BEGIN IMMEDIATE;
UPDATE trials
SET state = 'succeeded', result = :result, result_hash = :hash
WHERE id = :trial_id AND state = 'running'
  AND token = :token AND lease_until > :now;
-- rowcount=1：同事务将对应 attempt 标为 succeeded，然后 COMMIT。
-- rowcount=0：读取原状态分类，不得降级成无条件 UPDATE。
-- 仅当已 succeeded 且 token 相同：
--   hash 相同 → idempotent；hash 不同 → conflict。
-- 其他情况 → rejected。以上读取也在同一事务内。

租约有效区间不含右端点：lease_until=5 时，now=5 的完成与续租都失败，重新领取允许 lease_until≤now。续租同样检查 running、token 与未到期条件，迟到 heartbeat 不能恢复所有权。生产服务需在取得锁后的短事务内读取数据库权威时间，不接受 worker 自报 now。实验注入逻辑时刻，用于确定性地重现这一边界。

逻辑时刻具体事件数据库与外部世界
0 / 1W1 领取 token=7、lease_until=5；下游记账 7 单位后 W1 暂停trial 仍 running；费用已在独立数据库提交
2W2 试图提前领取返回 null，W1 有效租约没有被抢走
5尚无人重领，W1 续租与完成均到达边界两者更新 0 行；证明必须检查 lease，而不只是 token
6 / 7W2 领取 token=8、lease_until=11，再记账 7 单位；W1 持 token=7 提交此时 running 与新租期都有效，旧写入仍更新 0 行；这里单独检验 token 条件
8 / 9W2 完成 new-result；W1 又迟到提交 old-result新结果更新 1 行后成为终态；旧写入更新 0 行，不覆盖结果
12W2 重传相同结果，再重传不同结果前者 idempotent，后者 conflict；二者都不写结果。读取既有成功无需重新满足租期

消息投递仍需面对 worker 完成后、确认消费前崩溃，以及数据库提交成功但响应丢失。消费者、结果数据库和下游计费不属于同一原子边界。结果数据库的条件写入允许重复查询某次提交是否已被接受，但不能由此推出下游只执行一次。

结果去重与外部副作用

token 只约束实际验证它的资源。实验的调度数据库拒绝 token=7，但独立下游账本不读取调度数据库；时刻 1 已提交的 7 单位不会随着时刻 9 的拒绝而回滚。最终只有一份有效结果，却有两个账目、合计 14 单位。结果至多一次生效、执行至多一次和计费恰好一次，是三个不同的保证。

下游若原子保存某资源已见的最大 token，可以拒绝随后到达的更小 token；但旧动作先于新 token 到达时，动作已经发生。fencing 提供顺序屏障，不提供去重或补偿。发邮件、扣费和修改生产系统需要按业务动作确定跨 attempt 稳定的幂等键，并遵守下游契约；各 attempt 使用不同键无法对这类重试去重。

幂等范围键与载荷同键处理与边界
创建实验(tenant, operation, Idempotency-Key) + 规范化规格 hash同规格返回旧 ID，异规格冲突；唯一约束与创建必须在同一事务中。不能跨租户泄漏结果
提交结果(trial_id, accepted attempt/token) + 结果/manifest hash同 hash 返回已接受结果，异 hash 冲突；旧 attempt 即使碰巧交相同内容也无权成为获胜者。实验用 UTF-8 结果字符串的 SHA-256，服务需规定完整 manifest 的规范化方式
外部业务动作(tenant, logical_action_id) + 完整动作载荷 hash重试同一个动作复用键，新的业务动作才换键；超出下游键保留期不可盲重放。能力取决于下游，控制面自建表不能替它承诺

响应超时留下的是执行状态未知。恢复流程优先凭业务动作 ID 查询，或按下游幂等契约重试。Stripe 文档规定了同键参数比较、首次结果返回（包括某些错误结果）和键清理后的行为：键被清理后重用可能成为新请求。若下游既不支持幂等也不能查询，则记录 unknown，进入人工确认或补偿。outbox 可以原子保存本地业务状态与待发送事件，但投递仍可能重复，消费端仍需去重。

仓库修复中，同一 trial 的两次 attempt 可以各自生成补丁，平台只发布被接受结果对应的不可变 diff；W1 失去租约后不得写入 W2 的工作目录。自动创建 PR 是生成补丁之外的另一个业务动作，需要独立的稳定动作 ID 与查询、幂等协议。因此这里将默认结果限定为可审查 patch，不自动执行运维动作。

取消与完成的事务顺序

取消包含四个独立事实：停止接受结果、通知 worker 停止、确认环境退出和费用结算。本章采用先成功提交终态事务的一方获胜的规则。cancel 只更新 queued/running，complete 只更新合法 running；取消先提交，完成、续租和重领均失败；完成先提交，后到的取消返回 already_terminal，不能将成功改成 cancelled。该规则确定结果接受顺序，不承诺点击取消时立即撤销远端工作。

取消的核心条件 · 与 complete 竞争同一行
UPDATE trials SET state = 'cancelled'
WHERE id = :trial_id AND state IN ('queued', 'running');
-- 更新 1 行后，同事务关闭当前 attempt 的结果写入资格。
-- cancelled 在实验中只表示不再接受结果，不是 worker 已退出。

实验串行安排两种合法事务顺序：时刻 20 领取、21 取消、22 完成/续租被拒、23 重领失败；另一 trial 在 30 领取、31 完成、32 取消更新 0 行。这检验状态转移契约，不是线程竞态覆盖。真实服务还需要把 experiment 的取消标记和 claim/complete 的判定放进一致的事务协议，防止实验已取消、某个尚未遍历到的 trial 却被领取。

Go 的 context.CancelFunc 官方说明明确表示它不等待工作停止。goroutine 必须观察 Done，HTTP 调用需要接收 context，子进程与环境还需显式终止和回收，跨进程 worker 则经控制协议接收取消。服务接口因而需分别暴露 cancel_requested、worker_stopped 和 settlement_pending；取消后的未知费用继续对账。

重试准入与预算预留

重试次数、执行截止时间、并发或速率额度与金钱预算分别限制不同资源。按 provider/model 共享限流，可避免每个 worker 将公共额度视为独占；可重试故障则按服务契约处理 Retry-After、指数退避与 jitter。上下文超限、鉴权失败和确定性参数错误不应原样重放；超时且结果未知的请求先进入幂等或查询协议。

以下预算算法属于服务设计，尚未纳入实验。每次可能付费的调用先在共享事务中预留可验证的成本上界 r，满足 spent + reserved + r ≤ budget 才准入。确认花费后，reservation 转为 spent，只释放确定未使用的余量。超时且可能已计费时保留 unknown reservation，新 attempt 另行申请额度。如果下游没有可约束的费用上界，这条准入规则也无法提供硬费用上限，需要下游限额或保守暂停。

以合成单位手算：budget=20，第一次预留 8 后超时，reserved 仍为 8；第二次预留 8 后成功结算 7，此时 spent=7、reserved=8、可用=5。第三次仍需 8 时必须拒绝，即使此前只有一次已知成功。实验中的两次 7 单位记账，展示了失败 attempt 的外部费用为何也属于总成本。

租约、模型超时和实验 deadline 对应三个时间范围。租约决定失联恢复窗口，续租让正常长任务保持所有权；模型超时约束一次 RPC；总 deadline 包含整个实验的排队与退避。重试前，剩余时间必须容得下退避和该次调用上界。短租约增加误重领与重复费用，长租约拖慢故障恢复，选择时需要结合 heartbeat 延迟与恢复时间。

服务级故障与负载实验

服务化之后的实验需要两个真实 worker 和一个可制造 429、响应超时、迟到响应的本地假模型服务。领取后终止一个 worker，等待租约失效，由另一个完成，再重放旧 token。创建接口可重复提交同一实验 10 次，检查只产生一个逻辑实验且同 key 异规格冲突。取消后迟到结果、对象上传失败与数据库暂不可用分别注入并保存请求及事务顺序。这些是尚未执行的服务实验方案，离线脚本不覆盖进程与网络行为。

大轨迹先上传临时对象并确认完成、校验 hash，再由数据库事务发布不可变引用；上传成功但数据库提交失败会产生孤儿对象，定期按保留窗口清理。不能先提交引用再上传，也不能仅凭客户端上报 hash 宣称对象可读。数据库队列先用 100 个假任务测排队与争用，负载报告应记录机器配置、并发、任务时长分布、吞吐、排队时间、数据库争用、过期重领数、旧提交拒绝数与未结算成本；增加中间件要对应实测瓶颈。

报告完整性与实验可比性

评测平台聚合指标前，需要确认计划的 task×repeat×arm 均有可解释记录。数据库 succeeded 数不能代替能力通过数；评分未完成、artifact 不可读、费用待结算均需显式记录。调试报告可以暂时不完整，最终结果则不能只汇总先完成的短任务或成功重试者。P1 的 complete、P4 的分项评分与本章 attempt 账本共同指向同一份不可变实验规格。

报告保留规格 hash、领取与续租及提交顺序、最终接受者、所有 attempt 的费用和原始 artifact、评分版本与排除样本理由。修改提示词、模型或预算产生新条件；只升级评分器时，对所有比较条件使用同一版本重评，并保留旧分数。这使 P9–P10 的改进能够与额外采样、评分规则变化区分开。

可取消 worker pool 的实验方案

Go 有界 worker pool 可用于检查跨层取消：逐层传播 context，分别记录取消请求、worker 退出和环境回收的时刻，用等待机制确认 goroutine 退出，再用竞态检测覆盖同时 claim/cancel/complete。取消前后的 goroutine 数量只提供泄漏线索，无法单独确认目标工作已经退出。状态表、故障日志和负载记录可进一步说明数据库队列的适用范围。

创建 PR、长时间构建和共享模型额度会分别增加外部动作幂等、环境隔离与共享预算要求。这些约束需要对应的服务级故障注入；离线 lab 的 20 条顺序观测仅验证前述数据库条件与逻辑时序。
