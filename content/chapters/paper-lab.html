STOP、DGM 与 HGM

这几项工作修改的对象、保留候选的方式和选择下一次修改起点的方法各不相同。下面对照它们的控制流程，重点看 DGM 的档案选择和 HGM 的谱系指标。

修改对象与选择方法

工作核心对象精读入口不能直接推出

STOP 让代码改进器改进自身元效用如何由下游任务构造基础模型也在自我训练

DGM：档案与父代选择

论文 v3 的算法把通过有效性检查的候选加入档案，不要求它即时胜过父代。其父代权重含 sigmoid(10 × (score − 0.5)) / (1 + n_children)，其中子代计数指仍有代码编辑能力的子代；这会抑制已经被反复展开的节点，方向不是“孩子越多越优先”。

本站分析：研究档案可以保存弱分支，用户正在使用的版本却不必随之降级。维护两个引用：archive 供探索，incumbent 供使用。若把它们都叫 keep，就会把“允许搜索暂时退步”误解为“允许生产版本退步”。

最关键的对照：让初始 agent 始终担任修改者，与让改进后的 agent 继续参与修改比较。还应分别关闭档案探索、打乱诊断反馈、增加普通 best-of-N 的采样预算。只有对照回答了不同问题，消融才有解释力。

HGM：CMP 有三种不同的含义

理论 CMP 关心未来搜索后，从某个支系终选出来的 agent 的期望效用；§3.3 的在线估计量则合并支系成功/失败计数，并配合自适应评估。附录 D 的回顾性实证目标用后代中最好的经验均值，且排除支系根。这三者不能互换。

定理的限制包含：只关心最终 agent、试验可重复、证明不耗预算、每次自改耗一单位预算。实际系统里的有限样本估计、非平稳任务和异构计算成本并未因此得到最优性保证。

本站算例：支系 A 有一个 9/10 和一个 1/10 的后代；B 有两个 6/10。按合并通过率，A=50%、B=60%；按当前最佳后代，A=90%、B=60%。指标选错会让结论反转。若给 A 的强后代再分配更多测试，合并通过率也会改变，即使没有生成更强的后代——因此必须把搜索策略和观测过程一起分析。

一个可做的元改进实验

  1. 准备若干独立起点与任务族，固定基础模型和总调用/token 预算。
  2. A 组冻结改进器；B 组允许更新改进器；C 组用同预算随机搜索。每组重复完整搜索轨迹，不能仅重复末代测评。
  3. 各组只在开发数据上选终选候选；对新任务集运行一次预先规定的确认实验。
  4. 报告终选效用、达到目标所需预算、失败搜索比例和成本曲线。不只展示最成功的一条轨迹。

如果 B 只在训练过的仓库占优，跨仓库没有优势，应收窄为“这个任务分布上的搜索收益”。如果 B 优势在预算对齐后消失，优先接受“更多计算解释了涨分”。这些都是有价值的负结果。

练习：为什么“后代越好”不一定证明祖先更会改进？

强祖先可能获得了更多展开预算、更容易的任务、更强的外部模型或人工帮助。比较时应固定剩余预算、随机化资源分配，并用独立重复的完整搜索衡量祖先的边际贡献。仅从一棵已经选优的树做相关分析，不能单独建立因果解释。
