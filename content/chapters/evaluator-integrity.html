评分器误差与权限隔离

候选得分异常升高，可能是能力提高，也可能是评分器误判、样本遗漏或结果被篡改。这三类问题需要分别检查测量规则、数据完整性和执行权限。

评分失真从哪里来

类型具体例子验证方式
评分实现错误正确结果因浮点精度或合法替代解被拒参考实现、边界输入、变形测试、人工复核争议样本
目标代理失真优化可见评分却损害真实用户目标独立审计指标、分布外验证、优化强度曲线；不能只换更强 judge
测量完整性破坏候选修改测试、删失败日志、伪造 pass外部执行身份、评分服务、只追加审计与工件核验

奖励模型过度优化说明：代理分数越高，真实目标未必越好。这与“测试文件被修改”是不同机制；只解决权限隔离仍然可能优化错目标。

候选与评分器的权限隔离

候选执行域拿任务输入、允许的工具与临时工作区；控制域保管评分器、确认数据、预算、版本发布指针和完整日志。同一进程、同一账号下的不同 packageId 是组织边界，不自动是安全边界。只读挂载防写，不防读取答案；一个 hash 只能标识内容，不能证明数据来源可信。

控制域从候选产物计算分数，不能采纳 agent.reported_score。超时由控制域计时并终止对应工作负载；把 timeout 改成结果字段本身并不构成进程隔离。本仓库的 Python lab 只做可信输入的统计分析，没有实现这一执行域。

LLM judge 的校准协议

  1. 拆开任务正确性、偏好和约束；可用外部断言的部分先用断言。
  2. 建立含合法替代解、冗长错解、格式攻击与边界案例的人评子集。记录专家分歧，不能假定人评永远无误。
  3. 隐藏候选身份，交换 A/B 顺序复评，固定 rubric 和模型版本；对长度、位置和自我偏好分层统计。
  4. 报告错误接受率、错误拒绝率和不确定比例。judge 返回 unknown 时转人工或保持现状，不能静默当 pass。
  5. 独立保留校准集之外的 judge 审计样本；被测分布变化后重新校准。

位置偏差、冗长偏好等现象已有系统研究，多 judge 投票也可能有共同偏差。应把它当测量模型来验证。

CoT 与 latent reasoning：没有文字证据怎么办

可见推理可以是监控信号，但不保证忠实或完整；没有可见推理时，不能用一段事后解释补出同等证据。依然可以测最终行为、环境副作用、工具轨迹、诱导条件下的失效率，以及监控在固定误报率下的召回。激活层探针或机制可解释性需要白盒访问和额外验证，不是 API 场景里随手可用的替代品。

评估监控时把攻击生成、阈值校准和最终评估分开。告知是否有监控、可见的奖励结构、上下文长度都可能改变行为，应作为实验条件记录。AI Control 的研究视角是评估部署协议在对手模型下的风险，不是从一句“我没有作弊”推断系统已对齐。

回滚究竟撤销了什么

代码指针回退只撤回未来执行逻辑。已发出的邮件、已泄露的数据、已写入的共享数据库不会自动消失。需要记录 effect journal，为可逆操作定义补偿，为不可逆操作设置试运行或预提交门。候选先在独立环境确认，再由控制域提升版本；不要先修改真实用户会话，再希望失败后换回指针就恢复一切。

DSH 提供值得研究的机制，但其固定版本安全声明明确说尚未经安全审计、不能视为安全或生产就绪。这里的隔离设计要求不能由“采用 DSH”替代验收。

练习：没有检测到作弊，能写“作弊率为零”吗？

不能。还缺检测器灵敏度、覆盖范围与样本量。即使检测完美且 n 次独立试验零违规，常用近似的 95% 违规率上界仍约为 3/n；相关试验、漏检或自适应选样会破坏该解释。报告“在这些测试条件下未观察到”并给出边界。
