项目展示与面试准备

应用工程、评测工程和平台后端会追问项目的不同部分。本章整理岗位样本、投递安排和项目面试练习，可以从第 1 周开始使用。

岗位方向招聘原文所体现的工作对应的项目部分适配边界

按岗位选择展示内容

应用方向：用户工单→检索→工具→结果→失败兜底，展示具体业务约束。平台方向：租约、fencing、幂等、取消、成本和容量，关联自己已有后端经验。评测方向：任务有效性、独立评分、污染控制、统计与负结果。研究方向：定义假设、固定预算与机制消融，并说明没有证明什么。主简历只突出一个方向，其他部分留作追问。

简历条目示例

模板：方括号只能填写自己实际测量的结果
构建 RepoOps Agent 评测原型，覆盖 [N] 个任务 / [G] 个家族，
实现版本化任务、独立证据评分和 [实际完成的可靠性机制]；
在 [模型修订]、[预算] 下比较 [A/B]，配对成功率变化 [Δ及区间]，
成本变化 [值]；发现并修复 [具体失败]，复现入口为 [链接]。

若只完成离线夹具：明确写“规则策略、教学任务、未测真实 LLM”。
若实验无显著收益：写“建立比较协议并识别 [退化/不确定性]”。

不使用“精通所有 Agent 框架”“准确率提升 50%”这类无分母表述。示例代码来自课程时，说明自己新增了哪些模块、做了哪些实验；依赖项目的能力不能全部归功于自己。

45 分钟模拟项目面试

  1. 0–5 分钟：问题、用户、约束和演示。无需先讲一遍所有框架名称。
  2. 5–15 分钟：拿一条真实轨迹走通数据与控制流。追问某个工具失败时如何恢复，哪份数据由谁读取。
  3. 15–25 分钟：现场做一个设计修改：worker 从 2 个到 20 个，或者换模型服务。说清预算共享、幂等、取消和 bottleneck。
  4. 25–35 分钟：质疑实验结论：任务是否同源、为何重复不独立、是否调过确认集、成本是否可比。
  5. 35–45 分钟：展示失败实验、开源选择依据和下一步。遇到不会的内容，说明当前实现和待验证假设。

编码与模型基础

每周留两段 45 分钟：一段练数据结构/算法与复杂度，一段练项目相关编码。建议顺序：JSONL 校验器、Top-K 检索合并、有界并发与取消、指数退避、幂等写入、配对统计。Go 方向补 goroutine/channel、内存与 race；Python 方向补异常边界、迭代器、类型与异步 I/O。算法题尽量在无助手条件下讲思路、写实现、举反例。

模型基础安排三次白板练习：注意力的 Q/K/V 和序列长度成本；prefill/decode 与 KV cache；采样、上下文和结构化输出的边界。若目标 JD 要求训练，另补 SFT/LoRA 与偏好优化的原理和真实小实验；本主线不声称已经覆盖模型训练岗位。

作品目录与自查

入口 README 包括运行命令、真实/离线模式、演示和完成范围；数据卡说明来源和拆分；架构 ADR 说明取舍；报告能回到 trial；故障复盘展示定位；贡献链接注明状态。请另一人在新环境试跑，补齐遗漏的依赖与步骤。不要把公司的代码、日志或个人信息当面试材料。

自评每项 0–2 分：可复现、任务有效、评分可信、恢复可靠、预算完整、统计恰当、源码理解、表达清楚。0=没有，1=有实现但证据不足，2=能演示并解释反例。分数用于检查遗漏，不设统一的投递门槛。记录面试中没能回答的问题，下一周优先补齐其中两项。

回到 项目介绍，或用 岗位、面经与源码映射 查找对应的源码和问题出处。
