工程 / 17 · 包与边界

包案例：按依赖边界组织能力

仓库修复助手从本机执行迁到远程环境时，文件、进程、终端与语言服务必须一起迁移。Provider 的替换成本取决于包边界：接口由谁定义，执行环境由谁管理，消费者依赖哪些行为。本章以这次迁移为例，讨论包组合、接口兼容性与权限之间的关系。

案例范围本章以 DeepSeek Harness 的历史包清单为案例，讨论包组合、接口兼容性与权限之间的关系。54 个分组、288 个包来自本站保留的历史清单，未保存生成时的上游 commit；不代表当前版本的包数量、可安装性或依赖图。实际选型以目标版本的包名、注入方式与构建命令为准。迁移案例用于分析设计，未在运行时验证。

从产品约束确定包组合

设输入为任务 repair-42、仓库提交 base-A 与补丁 patch-B。任务需要修改工作副本并运行指定测试，但不能接触宿主凭据、不能改评测器，结果必须能绑定到这两个版本。一个功能齐全的 bundle 可能便于安装，却带入任务不需要的工具和权限。

产品约束最小能力边界不该顺手带进来的能力
知识助手：读取获准文档并给出出处身份与文档授权、检索接口、引用结果；索引写入由独立任务拥有为了解析文档给在线问答进程任意 shell；把 UI 隐藏当访问控制
仓库修复：读写工作副本、启动受限测试同一个工作区身份下的文件与进程 Provider；修改与运行结果可对账宿主文件系统、共享凭据、评测器写权限；不能用 shell 绕开受限文件工具
评测平台：对固定候选评分候选只读输入、独立执行器、不可由候选改写的评分及结果存储在候选进程中加载评测管理凭据；让候选通过插件管理器改评分规则

三者可以复用接口或只读数据结构，但未必应该共用运行进程、包组合或存储权限。复用代码与共享信任域是两次独立决策。RSI 场景更需分开：候选可以改自己的工具实现，不意味着它能改独立的验收器。

历史包分组索引

历史清单把 core 放在会话、提示词、工具与循环主干，llm 放在模型适配，fs / shell / sandbox / subprocess 放在执行能力，session 放在持久化与投影，cordis 放在运行时扩展。dsh-tool-* 通常是模型工具入口，dsh-bundle-* 是安装组合，普通 dsh-* 包提供其他能力。前缀能帮助找入口，不能替代 exports、依赖与权限检查。

例如历史 fs 族中，fs 定义能力，fs-local 提供本地实现，fs-observation-policy 消费意图事件施加策略。目录归组只是文档分类；真正边界要看消费者导入了哪个接口、运行时注入了哪个实现、谁能旁路访问系统资源。一个包只出现在一个分组，不等于它只依赖那个分组。

Provider 替换与执行环境一致性

假设文件 Provider 已切到沙箱，bash 仍在本机。模型先读到沙箱中的 /workspace/src/a.ts，再执行 npm test；同名路径的宿主文件可能完全不同。两个调用分别成功，测试结果却无法说明刚才的补丁是否有效。组合层需要保证文件、进程、PTY 与语言服务属于同一个执行环境，仅在各工具内部依赖抽象接口还不够。

执行环境契约示例：标识为设计字段，非 DSH 配置语法
任务输入：task=repair-42, base=base-A, patch=patch-B
组合约束：fs.world = process.world = language.world = sandbox-7
工作区身份：sandbox-7 / checkout-42；不能只比较路径字符串
执行顺序：创建工作副本 → 写入补丁 → 在同副本跑测试 → 导出证据
反例注入：process.world 改成 host
验收目标：组合阶段拒绝，或运行前明确失败；不能返回一份“成功”报告

环境一致之后，还需要检查远程 Provider 是否保持文本编码、路径规范、符号链接处理、取消、错误分类与资源释放的约定。本地 rename 的原子性不能自动推广到另一种存储。替代实现满足消费者依赖的语义时，迁移才能局限在 Provider 绑定；否则接口契约与消费者也需要调整，相同方法名并不足以保证兼容。

拆包的收益与成本

三角结构让独立变化的角色能够独立发布或替换。若只有一个消费者、一个不可替代实现，且两者总在同一变更里演化，包内接口通常已经足够。拆包会引入版本同步、导出面、初始化顺序与集成测试成本；模糊的复用预期很难抵偿这些成本。

第三方依赖同样需要按实际边界比较。成熟解析库可以替代自有解析代码及部分边界测试，但也可能带来 ESM / Node 兼容性、原生构建、安装脚本、许可证和维护风险。依赖的轻重需要在锁定版本和真实启动路径上衡量，包括安装成本与需要自行维护的机制。bundle 可以减少组合错误；它实际带入的 Provider、工具和权限仍需单独检查。

工具的注册来源历史清单中 dsh-tool-cordis 只列 cordis_inspect_list / cordis_inspect_query；define / run / stop / undefine / inspect_self 被归到 dsh-cordis-host-runner 提供的动态会话工具，不在该发货工具目录。dsh-plugin-manager 还注册 plugin_manager 并进入 boot.pkgs。因此，按 dsh-tool-* 前缀检索会漏掉部分工具，完整工具面需要沿注册入口继续查找。

本地到隔离环境的迁移实验

实验从固定目标 commit、锁文件和实际 profile 开始，记录包依赖闭包与接口到 Provider 的绑定。随后让同一个消费者分别使用本地和隔离环境运行 repair-42，对照读写与测试看到的工作区身份、补丁摘要和结果。再故意混入宿主进程 Provider，检查组合阶段或执行前是否拒绝；卸载后检查进程退出和工作副本释放。安装成功仅覆盖实验的准备阶段，执行环境一致性与资源清理需要这些运行结果分别支持。
