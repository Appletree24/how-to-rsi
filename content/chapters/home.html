Agent、Harness 与递归自我改进

How to RSI

自我改进涉及两个不同的问题：系统怎样完成任务，以及它怎样改变完成任务的方法。这里从 Agent 的执行过程出发，讨论运行环境、评测和候选搜索，再进入递归自我改进的研究。

从一次执行到下一次改进

一个代码 Agent 找到错误、修改文件、运行测试，这些动作发生在 Harness 提供的工具、上下文和权限之内。修改能否保留，还取决于另一套过程：测试覆盖了什么，评分是否可靠，效果是否来自额外预算，以及下一轮是否仍然成立。

当改动对象从任务代码转向提示词、检索策略乃至候选生成方法，执行与评测就逐渐连成了改进循环。递归自我改进一章用一个有限解析器实验区分解题器与改进器；研究问题与实验约定进一步讨论比较对象和成本口径。

三个工程场景

知识助手

知识助手需要从多版本文档中找到当前有效的证据，再据此回答。检索命中、上下文保留、答案正确和引用完整是不同环节；增加候选数也可能挤掉关键段落。

这一部分从 RepoOps 只读工单实验开始，依次讨论任务与数据、工具循环、检索与上下文和评分。检索实验包含旧版手册干扰、预算裁剪和权限过滤的具体例子。

仓库修复

从返回建议到提交 patch，系统开始承担文件、进程和外部副作用。测试结果取决于代码，也取决于测试所在的环境以及候选能修改哪些内容。

隔离执行与独立验证讨论修复任务的环境和产物传递，轨迹与成本记录执行过程，对照实验比较固定预算下的结果。现有 RepoOps runner 只读；代码修复与 Harbor 接入在这些章节中作为扩展设计展开。

评测平台

worker 失联后重跑，同一个逻辑任务可能产生多个 attempt。平台需要分别处理结果归属和实际费用，再把完整观测送入统计分析。

租约与结果提交用 SQLite 实验解释迟到提交、取消和幂等；评测平台设计连接执行与报告；配对比较和评测实验给出可重算的判断过程。

Harness：模型之外的执行系统

模型请求由哪些材料组成，工具何时获准执行，取消后还有哪些工作未结束，崩溃后如何处理结果未知的动作——这些问题决定了 Agent 的运行行为。

相关章节从职责与架构选择展开，进入上下文编译、调度与预算、会话恢复和故障测试。其中既有 DeepSeek Harness 固定版本的文档分析，也有通用设计方案；来源和适用范围随具体内容说明。

自改与元改进

修改提示词或代码后表现提高，说明这个候选在相应条件下更有效。若连产生候选的方法也被修改，还需要单独比较改进器。论文机制介绍相关研究的控制流程，候选搜索讨论反馈驱动的版本迭代，元改进实验比较冻结与更新改进器的过程。

本地实验

仓库包含几个不依赖模型服务的 Python 实验，分别运行规则 Agent、检索与租约故障、统计评测和有限搜索。命令在仓库根目录执行，使用 Python 3.10+ 标准库。

Python 实验入口
python -m projects.repoops.runner demo
python projects/repoops/retrieval_failure_lab.py
python projects/repoops/lease_failure_lab.py
python labs/eval_lab.py demo --output lab-output
python labs/improver_lab.py

各实验的数据、输出和限制见 RepoOps、评测实验和改进器实验。规则策略与合成观测用于解释机制，结果不代表真实模型表现。
