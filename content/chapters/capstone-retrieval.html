检索、上下文与记忆

故障记录建议回滚，新版手册却要求扩容连接池。增加文档版本与干扰内容后，单纯的词匹配会开始失效。本章逐项比较检索排序、上下文组装和记忆的影响。

词匹配基线的限制

Corpus.search 用小写英文词的集合重合数排序，最多返回 5 个标题；它不是 BM25，也没有中文分词或语义理解。英文教学夹具让机制清晰；改成中文工单、缩写和自然语言后，必须先测词法分词与同义词的影响。

从词匹配到混合检索

  1. 检索契约。输出 doc_id, revision, chunk_id, score, source，引用映射到不可变文档版本；同一内容重新分块不能让原有引用失效。
  2. 词法升级。实现或接入 BM25，并保留现有基线；先测试错误码、路径和函数名，因为它们常有精确匹配价值。
  3. 语义支路。固定 embedding 模型、归一化方法与语料 hash。用同一任务和候选池比较词法/向量/融合，而不是更换全部数据后再比较。
  4. 融合与 rerank。可用 RRF 合并排序：每个排序贡献 1/(k+rank)，k 在开发集固定。重排只处理前 m 条，记录增加的延迟与调用量。在选择集检查这些参数是否改善了检索结果。
  5. 上下文预算。按证据相关性、文档有效期和 token 预算选择内容；保留任务目标、已读证据 ID 与待验证假设。不要让“摘要更短”覆盖错误码或否定词。

检索评估和任务评估同时做

问题测量诊断实验
证据没被找到？有相关证据的任务上 Recall@k；多证据任务记录覆盖率把检索输出换成人工 oracle 证据
证据在列表里但排得太后？MRR；有分级相关标签时才用 nDCG固定候选池，仅替换排序
上下文把关键处截掉？证据保留率、上下文长度、最终成功率相同证据换位置、增加干扰、删除压缩
模型忽略证据？答案正确与引用支持分别评分oracle 证据仍错误则继续查生成/规则理解

无答案样本的 Recall 分母为零，应单独报告拒答质量；不能把它当作完美检索。一个文档包含正确规则不代表每个引用都支持结论，P4 继续处理。

记忆的版本与可见范围

短期状态保存当前任务、已经验证的事实和待办；长期记忆保存经验证的通用经验，不写入确认题答案。给 memory 记录来源、适用范围、创建时的代码/模型版本和有效期。运行测试任务时冻结记忆快照；禁止把 test_public 的评分结果回灌，再声称下一次是独立测试。

第一版用 memory.json 即可：{id, claim, evidence_ids, scope, revision}。读取记忆前校验 scope；用“billing 的修复经验误用于 checkout”作失败练习。若增加 Planner/Executor，多出来的调用与上下文也进预算，先证明单 Agent 的具体瓶颈。
