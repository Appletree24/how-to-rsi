RepoOps / P8 · 隔离执行

仓库修复的沙箱与独立验收

知识助手的“扩容连接池”是一条文本建议；仓库修复器写入配置后，产物还需要经过权限检查和实际执行。测试、环境与成功标记一旦落入 Agent 的可写范围，测试通过就可能失去意义。本章以一张 Harbor 修复任务为例，讨论从接收 patch 到独立验证服务行为的信任边界。

连接池任务的行为契约

任务仍是 checkout 的连接池耗尽，但不再接受 resize_pool 这个字符串作为完成。instruction.md 应说明公开负载范围、数据库总连接配额、允许修改的配置文件、运行时限与可观察的成功条件：在约定负载下不出现连接池耗尽，同时不越过数据库配额。哪些阈值属于合同必须公开；隐藏测试只能隐藏实例与组合，不能临时添加用户从未声明的要求。

池上限同时受单副本负载和数据库总配额约束。设同时运行的副本数为 n、每副本池上限为 p、其他业务占用与安全预留为 r、数据库配额为 Q，至少要满足 n × p + r ≤ Q。这个上界并不保证吞吐或延迟达标；事务持有时间、连接泄漏与重试放大仍可能导致耗尽。单副本测试因此无法覆盖更多副本下的安全性。这里给出任务模型，未报告服务性能实测。

应允许不同合法配置达到同一行为，不要求 patch 与人工答案逐字相同。若公开约束下仅改配置无法同时满足延迟和配额，正确产物应是有证据的不可满足说明或升级请求，而不是擅自放宽测试。本任务首先要由人工 oracle 确认可解，才能把 Agent 失败解释为能力问题。

执行权限与隔离环境

当前 RepoOps runner 只有 search/read/finish，返回建议而不修改文件。下文是迁移到仓库修复任务的设计，涉及 Harbor 任务、独立 verifier、patch 过滤与资源隔离；本仓库尚无可直接运行的 Harbor 任务，也未完成容器兼容实测。已有 JSON 轨迹提供追溯信息，安全控制则需要在执行环境与产物入口落实。

Host 上的 subprocess 不是沙箱；普通容器共享宿主内核，也不能仅凭 Docker 宣称可承受任意恶意程序。教学环境至少使用无真实凭据、无敏感宿主挂载、无容器管理 socket 的专用环境，并限制网络、CPU、内存、进程数、磁盘与时间。工具允许改配置，不代表系统其他路径天然只读；应把契约落实为文件权限、产物验证和独立验收。更强对手需要额外隔离设计，不能用本练习替代安全评估。

separate 模式与产物传递

Harbor 默认 verifier 与 Agent 同容器；显式设置 [verifier] environment_mode="separate"，或配置 verifier 专属 environment，才会使用独立环境。新环境不会自动继承 Agent 的文件修改，因此需要传递产物。官方在线文档还说明会复制 Agent 发布目录 /logs/artifacts/ 以及声明的 artifacts，按 source 路径恢复；因此不能误以为“只声明一个 patch”就自动过滤了所有不可信产物。实际行为需对锁定的安装版本核验。

直接把 Agent 修改后的整个工作区交给 verifier，会连同被篡改的测试、依赖、启动脚本与缓存一起带入。这里采用干净基线 + 已审查的最小 patch：恢复可信基础仓库与依赖，只把允许变更应用到指定路径，再由可信入口运行隐藏测试。独立容器分开执行位置，产物入口还必须阻止发布目录覆盖 /tests、解释器、启动入口或结果文件。

从冻结产物到可信裁决

  1. 绑定基线与环境。保存仓库 commit、任务版本、镜像 digest、依赖锁文件、构建命令与架构。Agent 交付的 patch 必须声明对应基线；不匹配不能静默挑一个能套上的版本。
  2. 冻结并收取产物。Agent 结束后停止可变写入，生成不可变快照/patch 与内容哈希，记录实际收取的字节。不能先审一个文件，稍后再从仍可写的路径取另一份来执行。
  3. 在隔离暂存区解析。限定大小、文件数、操作类型与允许路径；规范化后拒绝路径穿越、绝对路径、符号链接逃逸及未授权的文件模式/二进制变更。配置任务拒绝新增脚本、依赖、测试修改与额外可执行文件。不要先解包到可信目录，再检查文件名。
  4. 应用到干净基线。只在可信 checkout 上应用允许改动，冲突或基线 hash 不符是无效产物。应用后检查实际文件树与权限，不只相信 patch 的头部声明；保留最终树摘要供复验。
  5. 由可信入口验证。verifier 自己启动服务与负载，不调用 Agent 提供的“测试成功脚本”。隐藏用例、测试运行器与判分逻辑只在可信边界内；结果由 verifier 写出，Agent 自报的 reward 只是不可信文本。
  6. 提交完整裁决。关联 patch hash、环境、测试版本、原始输出与 trial。解析失败、缺失 reward、超时、基础设施错误和任务失败分开保存，未知状态绝不默认成功。

这条链同时解决可重现性：别人可以从同一 commit、同一镜像和同一 patch 重做验收，而不是依赖 Agent 容器里无法解释的残留状态。若专属 verifier 镜像预装测试，需按官方模式把可信测试打包进去；不能假定任何 separate 配置都会在运行时自动上传 tests。

作弊提交与拒绝位置

故意构造的提交应该在哪里被阻止为什么正常测试通过不够
删掉失败断言，或写一个 reward=1 文件patch 白名单拒绝；独立可信裁判不读取自报成功同环境 grader 可能被改写，返回码为 0 不代表业务成立
把配置路径变成指向测试目录的链接暂存与应用后的路径/文件类型检查只检查路径字符串会漏掉真实写入位置
配置只识别公开负载或测试标记，其他输入失败相同公开契约下的隐藏边界负载、不同副本数与顺序记住有限样例不是实现需求；隐藏用例也不能随意超出合同
关闭告警、忽略连接错误，却没有恢复服务外部请求成功率、延迟及数据库连接占用联合验证日志安静与服务可用不是同一个指标
无限创建进程或阻塞验证运行环境资源限额、外部 deadline 与清理Agent 自愿停止不是强制预算，也不能防残留进程

反馈本身也是泄漏通道。Agent 可见测试用于开发，最终隐藏 verifier 不能把完整测试源码、精确参考 patch、秘密文件路径或可反推出全部实例的输出回传给下一轮搜索。可以返回预定义的粗粒度失败类别；若在最终集上不断试 patch，即使没有直接读取测试文件，也已经通过反馈适配了测试集。P9 必须把开发反馈与最终确认分开。

仓库修复还要避免环境泄漏：公共镜像不应提前烘焙隐藏测试或答案，构建上下文与缓存不能把它们带进 Agent；Agent 与 grader 不共享可写目录、秘密环境变量或可访问的调试端口。日志导出同样受控。隔离文件读取只是必要条件，公开 issue 的既有补丁或训练污染也可能让基准偏易；报告来源、去重与公开状态，不能声称完全排除预训练污染。

单张 Harbor 任务的接入步骤

  1. 按官方 Create a task，用 harbor task init repoops-checkout 建目录，固定框架版本、镜像 digest 与安装日志；兼容性由这一锁定组合的实际运行确定。
  2. instruction.md 放行为合同；environment/ 放小型服务、公开日志与初始配置；solution/solve.sh 是人工 oracle；tests/ 放可信外部行为验证，不只断言配置等于某个常量。
  3. task.toml 配 agent/verifier 时限、资源、网络与 separate 模式，按安装版本配置产物传递。先运行 oracle、空 patch、错误配置及上述作弊提交，再接真实 Agent。
  4. 用 mini-SWE-agent 作执行基线，固定 provider、prompt、工具与预算，保留轨迹；与自研循环比较时只在观察到具体瓶颈后新增专用工具。读其 environment 接入与 Harbor Trial 生命周期，入口见源码映射。
  5. 把 Harbor 原始 status、reward、错误、耗时和 artifact 映射到 RepoOps 账本，同时保留原始值；映射规则版本化，不能将未知值折叠为通过。
官方 CLI 操作步骤 · 需先安装框架、容器运行时并填写任务
harbor task init repoops-checkout
# 按本章填写任务、环境、solution、tests 和 task.toml
harbor run -p repoops-checkout -a oracle
harbor view ./jobs

真实 Agent 名称与参数以锁定版本的 harbor run --help 为准。偏代码修复可选 SWE-bench 风格的 issue→patch→tests，偏命令行任务可选 Terminal-Bench/Harbor 形式。接入阶段可按公开标准挑 10–20 个可运行开发任务，记录许可、镜像、筛选与排除项；这一子集不构成完整榜单复现，也不得与公开榜单直接比较。确认集与熟悉工具、调试任务的样本保持隔离。

隔离边界的验证实验

锁定环境后，先运行 oracle、空提交与错误实现，确定任务可解且验证能识别失败；再提交修改可见测试、伪造 reward 与越界路径的产物，检查独立裁决及拒绝位置。超时实验确认外部终止与清理，增加副本数的实验重新检查连接配额。每次保存冻结产物、干净基线重放日志与任务/环境错误分类；Agent 的成功自述不参与裁决。框架适配缺陷可整理为带版本的最小复现，再提交开源 issue/PR。

产物隔离限制了候选修改裁判的能力。P9 转向另一项问题：在裁判、权限和预算固定时，失败反馈对候选搜索有多大帮助。
