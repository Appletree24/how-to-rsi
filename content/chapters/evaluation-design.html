自改进评估中的差值、不确定性与版本决策

同样的 80 道题各跑 3 次，基线成功 120 次，候选成功 128 次：总成功率从 50% 升至约 53.3%。这两个总数确定了平均差值，却没有呈现改善分布在哪些任务、任务之间是否相关，以及候选是否已经利用过这批数据。本章以这组假设数据为线索，从逐题配对推到统计界，再讨论选择偏差、重试指标和版本决策。算例用于说明方法，不代表模型实测。

从总成功次数到逐题差值

两边使用相同任务、相同的每题尝试次数，保留失败和超时。记每次成功为 1、失败为 0；先求每题的平均成功率，再用候选减基线。假设前四题的记录如下：

任务基线成功次数 / 3候选成功次数 / 3逐题差值 d_i
A1 / 32 / 3+1/3
B3 / 33 / 30
C0 / 32 / 3+2/3
D2 / 31 / 3−1/3

四题合计从 6 次成功变成 8 次，平均差值是 (1/3 + 0 + 2/3 − 1/3) / 4 = 1/6。总分提高没有掩盖 D 的退步。假设其余 76 题的成功次数分别为 114 和 120，就得到开头的完整数据：Δ̂ = (128 − 120) / (80 × 3) = 1/30，即约 3.33 个百分点。一般形式是：

先在题内平均，再在题间平均
d_i = mean_r(y_candidate,i,r − y_baseline,i,r)
Δ̂  = mean_i(d_i)

同题配对让两边面对相同的难题和易题，减少任务难度差异对比较的干扰；它没有消除运行噪声。运行顺序可随机化，避免一边总在服务拥堵时运行。相同 seed 也不保证不同模型或 API 使用相同的随机过程，配对的依据仍是任务与实验条件。

分析逐题差值 d_i，保留了双方在同一任务上表现的关联，例如都擅长 B、都容易被某种难题拖累。分别计算两组成功率的边际区间，再观察是否重叠，会丢失这层配对信息；区间重叠也不是这里定义的差值检验。如果两组任务并非同一批，记录中的同名 ID 无法建立真实配对，比较需要依据实际的抽样与运行协议。

由于每题重复次数相同，开头的两个总分足以确定任务宏平均差。若超时后少跑某些难题，再合并全部运行，难题就会获得更小权重。保留预定尝试的失败或超时、先在题内计算，可以维持原定的任务权重。按真实流量加权也是一种估计目标，但权重需要在查看结果前规定。

重复运行、独立任务与聚类

这组数据中，每题的 3 次尝试共享题目难度、上下文和评分规则。要推断新任务上的表现，bootstrap 应抽取 80 个任务差值：抽到 A 时，将 A 的全部重复运行一起带入，而不是把每条成功或失败记录独立抽走。重复次数增加可以减小题内运行噪声，却不会增加所覆盖的任务数。

“任务”也未必是独立单位。若其中 30 道题是同一仓库的相近 issue，它们可能都受同一个依赖版本影响。此时可按仓库聚类重采样，保留仓库内的关联；同时说明目标是按任务加权还是按仓库加权，两者并非同一个平均值。独立仓库很少时，再多 issue 也不能补出跨仓库证据。数据很少或差值全部相同时，普通 percentile bootstrap 还可能给出退化区间，窄区间本身不说明估计可靠。

本仓库 labs/eval_lab.py 的 compare 先算逐题差值，bootstrap_interval 再对这些差值重采样。它保留了任务内聚类，但没有自动识别仓库层级；相关任务需要在实验设计和分析中另外处理，不能直接套用后面的独立任务界。

把每题的 3 次重复增加到 30 次，对这里按独立任务数计算的 Hoeffding 半径，不能缩小 √10：N 仍为 80。更多真实重复可以改善每题成功率的估计，进而影响实际方差；直接复制记录则连题内信息都没有增加。compare 的分母和 bootstrap_interval 的重采样单位共同决定了分析实际利用哪一层信息。

仓库修复的 issue 可能共用依赖和构建环境；知识助手的多道问法可能依赖同一份文档。若结论要推广到新仓库或新文档，划分与重采样也需要对应到这一层级，同源改写无法提供等量的独立信息。按任务加权估计遇到一项任务的期望收益，按仓库加权估计遇到一个仓库的平均收益；大型仓库任务更多时，两者会不同。聚类单位与权重取决于推广目标。

Hoeffding 界与最小有意义提升

实验程序的版本门槛使用保守的单侧 Hoeffding 界，而不是 bootstrap 区间。设任务独立、来自同一目标分布，候选和比较规则在确认前固定；任务内可以有重复运行，只要每个任务差值仍满足 d_i ∈ [−1,1]。若真实平均差值为 Δ，Hoeffding 不等式给出 P(Δ̂ − Δ ≥ ε) ≤ exp(−Nε²/2)。令右侧为 α，就得到：

固定一次比较，每个方向分别计算
radius = sqrt(2 × log(1/α) / N)
lower  = max(−1, Δ̂ − radius)
upper  = min( 1, Δ̂ + radius)

对算例取 α=0.05、N=80，半径约为 0.274；代入 Δ̂=1/30，下界约 −0.240，上界约 0.307。观察到的提升只有 3.33 个百分点，这个界还容许明显退步，因而不足以确认改进。这不表示候选没有价值，而是这项保守判据需要更多独立任务或更大的效应。若观察差值仅为 0.03，同样不能通过。

下界控制预先规定的这一次比较中，高估真实提升的单侧误差概率；上界是另一个方向的单侧界。α=0.05 不让这两条界合起来自动成为一个 95% 双侧区间。它们也不处理任务相关、题库不代表部署分布、评分器系统性误判或反复查看数据后改候选的问题。

bootstrap 区间无法只从 120 和 128 推出。前四题已有逐题差值，其余题只有总数；相同总数可以对应集中在少数题的改善，也可以对应分散的改善，重采样分布会不同。Hoeffding 界只用有界性与 N，因此仍能手算，代价是保守。若使用更有力的方法，其假设、覆盖性质与候选选择过程需要预先确定；在保守界未通过后改选更有利的区间，会引入额外选择。

令 0≤δ_min<1 为事先约定的最小有意义提升；接受要求是下界仍超过它，而不是点估计刚好为正。将这个要求反解，可以看出任务覆盖与收益门槛的关系：

把门槛反解成任务数：只作敏感性分析
lower > δ_min
⇔ Δ̂ − sqrt(2 log(1/α) / N) > δ_min
当 Δ̂ > δ_min 时：
N > 2 log(1/α) / (Δ̂ − δ_min)²

# 固定假想的观测差值才能反解；这不是前瞻功效保证。
# 增加任务后 Δ̂ 也会变化，不能承诺“补到 N 就通过”。

这个式子让预算讨论具体起来：目标效应越接近实际收益门槛，所需独立信息越多。若预算只能增加同一批任务的重复次数，而不能扩展独立任务覆盖，这项分布无关界不会按运行总数缩小；若任务相关，连这里使用 N 的前提也要重新审视。

数据分离与反馈路径

假如我们看到 D 退步后改了提示词，再用同一组 80 题确认，第二轮候选已经吸收了这组题的信息。即使没有读取题目，反复根据总分选版本，也会把评分反馈变成训练信号。数据分离要切断的是这条反馈路径，而不只是文件访问。

数据在这个例子中做什么能支持的结论
开发集 D_dev查看 D 一类失败的输入与轨迹，改代码或提示词帮助诊断机制；分数不再是独立泛化证据
选择集 D_select在冻结的候选集合中选择待确认版本，记录全部查询支持候选选择；多轮反馈会逐渐消耗其独立性
确认集 D_confirm对已选候选与基线进行预先约定的比较，例如上述 80 题在抽样与统计假设下支持最终决策；看过结果再调参后，不再沿用同一次确认解释

分割时还要排除近重复题，并根据部署目标按仓库、任务模板或时间划分。把同一模板的改写分到三套数据，文件虽然分开，信息仍可能重叠。自适应数据分析研究讨论了复用数据后的泛化问题；保证依赖具体的复用协议，不能直接用于任意反馈循环。

多重比较与自适应停止

另一个手算说明为什么确认次数会影响结论：假设 K 次检验彼此独立、原假设全为真，而且每次误报概率恰为 α，则至少一次误报的概率为 1 − (1 − α)^K。K=20、α=0.05 时约为 64.2%。若每次误报率只是至多 α，这个数是相应上界；实际候选通常相关，也未必满足原假设，所以 64.2% 不是任意搜索过程的精确误报率。

对预先固定的 K 个比较，且每个检验本身仍然有效时，用 Bonferroni 将每次显著性水平设为 α/K，可以控制家族错误率，不要求比较独立。但若候选是根据同一确认集的反馈生成的，除以 K 不会修复单次检验已经失效的问题。边跑边看、通过即停也改变了抽样规则，需要适合顺序检验的协议，而非继续引用固定样本量的一次性界。

可用 python labs/eval_lab.py selection-bias --candidates 30 观察筛选效应。程序设定所有候选真实成功率均为 50%，只按开发分数选最好者，再比较其新数据分数。这是合成数据演示，不是候选能力评测；调整候选数时，观察筛选后的开发优势是否在新数据上保留。

这个反例分离了抽样误差与选择偏差：增加同一开发集上的候选数量，可能抬高最高分，却没有增加新任务证据。全部候选、查询次数与终选规则共同描述了选择过程，最终确认则在候选冻结后进行。持续查看结果需要明确的序贯设计；固定样本量的一次性错误率不适用于自适应停止后的结果。

重试成功率与重复执行可靠性

回到任务 A：候选 3 次成功 2 次。若从这 3 次结果里等概率、不放回地取 2 次，共有 C(3,2)=3 种组合，每种都至少有一次成功，但只有一种两次全成功。因此该题的 pass@2=1，pass^2=1/3。两个数并不矛盾，问的是“有没有一个可用答案”和“每次是否都可靠”。它们是有限观测的估计，不保证未来重试也有同样结果。

一般地，一题 n 次尝试有 c 次成功时，组合估计为 pass@k = 1 − C(n−c,k)/C(n,k) 与 pass^k = C(c,k)/C(n,k)。要求整数 1≤k≤n；n−c<k 时前式为 1，c<k 时后式为 0。在固定成功概率 p 的独立同分布尝试下，它们分别估计 1−(1−p)^k 和 p^k，不能把观测比例 c/n 直接当作已知 p。pass@k 的依据是 HumanEval §2.1 与附录 A，可靠性口径参见 τ-bench 指标部分。

pass@k 也没有提供一个免费识别正确答案的选择器。任务 A 的三份产物即使有两份正确，实际系统仍可能选中错解。报告重试策略时，要一起给出选择规则、总调用成本及超时计分方式；先删除失败记录再算指标，会同时改变成功率和可靠性的含义。

指标的选择取决于实际执行路径。仓库修复若能在隔离环境验证补丁，可以评估“生成多份、按预定验证器选择一份”的完整过程，其结果未必等同于拥有真值 oracle 的 pass@k。知识助手若只向用户提供一次答案，就仍需估计这一次的正确率；会写入外部状态的代理，重复执行还可能带来重复副作用。调用次数、选择器、用户收到的产物和失败识别能力，共同决定重试指标能否描述部署表现。

将统计证据与工程约束合并为版本决策

假设生成候选前已把最小有意义提升设为 δ_min=0.02，候选总成本上限设为基线的 1.25 倍。沿用程序的决策顺序：

观测条件结论解释
出现严重违规，或总成本超过上限reject即使成功率升高，也未满足这次比较的可接受条件
通过上述检查，但 upper<0reject在所列假设下，已有退步证据
通过上述检查，且 lower>δ_minkeep下界仍超过预设的实际收益门槛
其余情况inconclusive保留当前版本；并非证明两者相同

开头算例在成本合格、未观察到严重违规时落入 inconclusive：−0.240 没有超过 0.02，0.307 也没有低于 0。若仍取 N=80，想通过这项 Hoeffding 门槛，观察差值需超过约 0.02+0.274=0.294。门槛严格来自界的保守性，不是所有实验都需要近 30 个百分点才有研究价值。“未观察到严重违规”同样只是当前测试的观测，不代表风险为零。

逐题结果保留了差值分布，全体候选与查询账本描述选择过程，失败类型及轨迹位置则支持错误分析。模型版本、harness commit、数据、评分器、环境版本和每题重复次数限定了比较条件。任务宏平均成功率之外，成本、延迟分位数和严重违规率能揭示提升伴随的代价；两个总分无法提供这些信息。

在这组算例中，点估计为 1/30；独立任务、冻结候选和固定一次比较的假设成立时，所用保守门槛仍未确认超过 0.02 的收益。因此，在成本合格且未观察到严重违规的条件下，程序保持当前版本。后续采样能解决的问题取决于限制所在：扩展任务覆盖增加独立信息，增加题内重复降低运行噪声，而数据复用和评分错误需要分别处理反馈协议与测量机制。由于算例没有给出完整 80 题记录，bootstrap 区间无法计算。
