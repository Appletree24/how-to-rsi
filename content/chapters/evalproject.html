评测平台：在重试、迟到与预算下作出可信裁决

候选版本的成功率依赖平台接受了哪些观测。worker 重领可能产生重复执行，失败记录缺失会改变分母，迟到提交还可能覆盖新结果。本章从任务身份、提交协议与成本账本出发，设计从执行到比较、再到发布的管线。仓库已有串行教学 runner、统计与租约实验；Go 服务、真实候选执行沙箱、DSH 适配器、确认集隔离及发布服务属于扩展实现。

平台契约与状态不变量

平台接收冻结的实验规格，而非随时变化的任务列表；输出完整的 trial 账本、配对报告与裁决，不直接相信候选自报的分数。一个逻辑 trial 由实验、版本、任务与重复序号确定；重试产生新的 attempt，不增加独立任务数。失败、超时、崩溃都必须保留在预定矩阵中。

非功能要求可检查的不变量取舍与限制
正确性每个逻辑 trial 至多接受一个权威终态；过期 token 不能覆盖新结果；矩阵不完整时不给最终裁决。重领可能重复执行，不能因此承诺外部调用 exactly-once。
恢复性重启后能区分 pending、有效租约、过期 attempt、已提交结果和取消状态。现有教学 runner 以完整 trial 提交，不是逐 token 恢复；崩溃前的费用可能已经产生。
隔离与可审计候选无权修改任务协议、权威评分器和接受结果；版本、输入、产物与裁决可关联。只读挂载防写不防读取泄漏；hash 便于追溯，不自动证明来源可信。
时延与吞吐分别记录排队、执行、评分和整组完成时间；以冻结负载报告吞吐与尾延迟。单次脚本 wall time 不是服务 P99；大任务拖尾不能通过删除超时来改善。
成本与资源每个 attempt 落实际已知费用、预留预算、取消状态；未知 usage 不伪造为零。拒绝迟到结果不会撤销外部费用；硬预算需要调用前准入与可执行的终止边界。
公平与保密生产扩展中按租户限制并发、隔离产物及确认集访问，调度决策可解释。多租户授权与容量隔离需要单独的工作负载和跨租户测试；单机公开任务实验不覆盖这些条件。

SLA 需要以任务时长分布、并发额度、模型限流与机器资源为前提。假如平均执行时间为 T 秒、稳定有效并发为 c，在资源与上游都不饱和的简化条件下，处理能力上限近似 c/T；若平均到达率已高于它，队列只会将过载转为长时间等待。尾部、重试和评分开销会让实际能力更低。

迟到提交中的 trial、attempt 与 token

设逻辑 trial 是某实验下的 (candidate-v2, checkout-0, run-0)。A 领取 attempt-1，获得 token 7；A 卡住后租约到期，B 领取 attempt-2，获得 token 8。A 随后返回“成功”。仅用 task_id 去重无法判断结果新旧，只检查 worker 本地时钟也无法阻止过期写入。

  1. 领取：控制库用短事务推进权威状态并发放单调 token。执行模型调用时不持有整段数据库写锁。
  2. 提交：按逻辑 trial、当前 token、租约有效性和未终结状态做条件更新；A 的 token 7 不再拥有提交权，B 的有效提交才可成为接受结果。
  3. 重复：B 因响应丢失再次提交，同一幂等标识应读回已接受结果，而不是再累计一份成功。
  4. 记账：A 与 B 已发生的执行费用都留在 attempt 账本；只接受 B 的结果不意味着只发生了 B 的成本。

禁止重试能避免部分重复执行，却会让临时失联永久破坏完整矩阵；接受第一次返回也不可靠，因为它可能来自已经取消的旧执行。预先规定的提交协议负责在恢复能力与结果唯一性之间建立一致规则，详细状态时序见 P5。

Phase 1 · 冻结任务、版本与比较条件

为每题固定输入、环境快照、断言、成本上限、超时规则与稳定 ID。记录 model、harness、environment、taskset、evaluator 的版本；开发、选择、确认数据分开。8–12 题可调试 runner，不能默认足以证明小幅泛化收益。一个仓库的多个相似任务可能相关，增加重复运行次数不能替代增加独立任务家族。

假如中途修复 grader 的误判，不能只给候选重算、沿用旧基线：评分器变了，可比条件也变了。应在同一新规则下重评分双方，保留旧报告与变更原因；若新评分需要旧轨迹未采集的事实，就必须补做执行，不能凭缺失字段猜测成功。

Phase 2 · 隔离执行与外部评分

基线和候选从各自干净环境运行，外部 verifier 收集产物判分。每条 trial 至少包含 task_id、run_id、status、passed、cost 与约束检查；平台另外保存 attempt、token、产物位置与原始终态。模型自述与进程外事实分开存储。packageId 标识代码，不是隔离机制。

Phase 3 · 统计裁决与发布策略

用预先规定的统计、成本和约束条件输出 keep / reject / inconclusive。平均成功率的增加不能抵消严重违规；证据不足时保持 incumbent，不等于已经证明两版等效。探索档案可以保留弱候选供后续搜索，用户可用版本只提升通过确认与发布策略的候选。两者不能共用一个指针。

DSH 适配器的 define/run/stop 精确 API 依目标版本文档确定。候选在独立环境中挂载和评测，控制域在通过裁决后提升版本，避免评测前就改变真实会话。恢复代码指针无法撤销已发出的邮件、支付或已提交的数据库事务；这些副作用需要单独的禁止、幂等或补偿策略。

工作负载扩展与架构变化

变更原方案的限制新增机制与验证
单机串行 → 多 worker整段 trial 持写锁阻塞并发；简单重试允许旧执行覆盖结果。短事务、租约、fencing；迟到与重复提交的确定性时序。先证明状态不变量，再压测。
只读回答 → 修改仓库结果不再只是文本，候选可污染测试或残留进程。独立 verifier、白名单产物、资源终止和干净重建；见 P8。
一次比较 → 搜索数十候选选择赢家引入乐观偏差，反复查确认集改变错误率解释。开发/选择/确认访问协议，冻结赢家后确认，记录完整搜索成本；见 P7。
本地公开任务 → 多租户私有任务taskset hash 不能替代鉴权，日志或共享缓存可能泄露题目。调用前身份与资源授权、分区存储、脱敏与保留策略、跨租户负例。
软预算 → 严格费用上限返回后累计成本发现超支时已经付费；客户端超时不等于服务端停止。调用前预留、供应商用量核对、并发上限；不可硬取消的调用仍有残余费用风险。

租约脚本在临时 SQLite 中执行故障时序并打印 JSON；评测 demo 写五组 input/result 与 summary；compare 从给定观测重新计算裁决；selection-bias 展示同质候选经过选择后产生的开发分数优势。这些实验分别覆盖状态机、测量协议和选择偏差，不包含外部模型执行服务。可执行文件与输入输出见项目说明、统计实验说明。

以 improvement 输入的副本做三次不同操作：删去一个失败 trial，应得到输入错误；把 reported_score 写成满分，应不影响重算；在完整合法输入里标记严重违规，应得到 reject 而不是输入错误。再看进程退出码：比较成功退出 0 只表示计算完成，最终裁决必须读取 JSON 的 decision；非法输入退出 2。逐步推导在 R6。

结构合法的伪造观测是另一类故障：如果每条输入都被伪造成合法成功，纯比较程序无法判断执行是否发生过。观测真实性需要由候选权限之外的 runner、verifier 与审计链路支持；更严格的 JSON schema 只能缩小结构错误，无法补上这个信任边界。
