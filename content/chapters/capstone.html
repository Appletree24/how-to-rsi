RepoOps Lab：从工单到实验

checkout 服务发布后报错。工单建议回滚，新版手册却要求扩容连接池。这个项目从一件小事开始：让 Agent 找到当前有效的依据，给出处置建议，然后检查它有没有答对。

先运行示例

在仓库根目录执行下面的命令。需要 Python 3.10+，无需安装依赖或配置 API key。

运行两种规则策略
python -m projects.repoops.runner demo
python -m unittest discover -s tests -v

结果写入 lab-output/repoops/summary.json 和两份策略报告。开发集有 6 张工单，来自 3 个服务家族。naive 直接采用工单建议，evidence 读取当前手册；示例中预期严格通过率分别为 0 和 1。这是人为构造的规则对照，用来检查运行和评分流程，不能据此判断 LLM 能力。

跟着一张工单走一遍

打开 tasks.json 中的 checkout-0。故障记录包含 error=POOL_EXHAUSTED 和建议 rollback_release；旧手册也支持回滚，但 revision 2 已将处置改为 resize_pool。

  1. 检索：用 search 查找故障记录与手册，用 read 读取原文。过期手册和不可信评论也在文档集中。
  2. 回答：用 finish 返回 resize_pool，引用 checkout-incident-0 与 checkout-runbook。
  3. 评分：循环结束后，评分器检查答案、引用是否存在、是否实际读过，以及是否覆盖要求的依据。

现在的程序只返回建议。P8 才加入隔离环境中的文件修改，随后比较不同搜索策略，以及更新修改器是否有效。

从现有代码开始扩展

仓库已有 12 张公开教学工单、Python Agent 循环、SQLite 结果存储、规则策略和可选的本机 Ollama 适配器。代码入口见 RepoOps README。

混合检索、Go 调度服务、Harbor 迁移、GEPA 接入和修改器实验由后续章节逐步实现，目前提供设计与练习。全程默认有 Python 和后端基础；如果还不熟悉异常处理、HTTP、事务或并发取消，可在相应章节多留一周。

16 周安排

按每周 10–15 小时估算。先读 P1–P4，完成数据、循环、检索和评分；遇到统计或论文问题，再回查研究章节。P11 整理了岗位样本和面试练习，可从第一周开始用。

周次章节项目进度求职安排
1P0–P1跑通示例；写任务卡和目标岗位矩阵收集 10 个真实 JD，选择一个主方向
2–3P2–P3真实模型最小闭环；检索失败可解释录制 3 分钟演示，找同行做项目追问
4P4评分规则通过反例；第一版作品页开始小批匹配岗位投递
5–6P5队列、租约与恢复；演练重复执行准备后端系统设计答辩
7P6能从一次回归定位模型/数据/基础设施整理一次故障复盘
8–9P7冻结协议，完成一次真实预算对照评测岗位版本简历与模拟面试
10–11P8迁移一个任务到 Harbor，跑通 oracle 与基线阅读并提交一个小型开源修复或测试
12–13P9固定预算比较反思搜索和随机搜索准备实验失败与取舍的说明
14–15P10完成改进器更新消融或报告证据不足研究工程方向技术报告
16P11第三方复现、项目答辩和查漏补缺按面试反馈改材料和能力短板

赶求职时，可先完成 P1–P7；P8–P10 提供后续深度。这些章节分别引入隔离执行、候选搜索和修改器更新，需要前面的评测系统支持。

需要读哪些开源代码

  • mini-SWE-agent：读 model、environment、agent 的职责，以及循环如何终止。
  • Inspect AI：对照 task、solver、scorer 的分离方式与运行限制。
  • Harbor：学习任务环境、验证器和基准运行，P8 迁移一张任务。
  • GEPA：在 P9 接入轨迹反馈，比较文本参数的优化方法。

阅读使用的提交版本和文件路径见 源码阅读索引。第一阶段只需要本仓库的 Python 实现。
