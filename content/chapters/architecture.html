Harness 架构：上下文、能力与执行环境

同一套 Agent 可以服务只读知识问答和有写权限的仓库修复，但两者对执行环境的要求不同。如果修复任务的 Bash 已切到远程沙箱，文件读取仍走本机，模型分析的代码与命令修改的就可能是两份仓库。Provider 替换因此涉及一组相互约束的工作区、身份和生命周期。

DSH 的分层、能力 seam 与事件域依据 固定提交 architecture.md。上下文编译和远程部署小节讨论通用设计方案，未提供 DSH 运行结果；末节说明 RepoOps 现有实现与接入差异。

Profile 与 Bundle 合成最终插件树

线上和本地行为的差异可能来自最终生效的配置组合。文档中 Profile 是 Harness home 内的具名组合，声明 bundle 并持有用户补丁与仓外插件；Bundle 分发配置行及所挂载代码。package.json 的 dsh.profile、dsh.bundle 描述两者身份。执行树由这些配置合成，单个 YAML 文件只能描述其中一层。

固定提交文档称 base 默认启用仅配置 HMR，headless/SDK/ACP 禁用，sdk-minimal 不挂该行；profile 补丁仍可改变选择。这个默认反映生命周期取舍，不保证所有热更新都无损：一次性 runner 中途替换存储或策略，可能让一次任务跨越两套行为契约。做评测时更合适的选择常常是锁住整次 run 的组合。

服务接口中的所有权契约

包与服务负责的事实消费者依赖的契约
core/session → ctx.sessions追加式日志、内存会话事件连续与投影语义，而不只是相同方法名
core/system-prompt → ctx.systemPrompt提示词与工具 schema 组装请求里没有未记录的模型可见补丁
core/tools → ctx.tools作用域注册、守卫与执行流水线未授权调用不能因绕过某个 UI 而放行
core/agent → ctx.agentsAgent 接口与存活注册消费者不依赖某个具体驱动器的内部状态
core/agent-loop → ctx.agentLoop默认回合驱动初始化、取消、结算、释放仍满足接口约定
core/scope（库，无 ctx 键）按 agent 作用域注册会话 A 的注册不泄漏到 B
llm/llm → ctx.llm适配器与流词汇取消与错误有稳定映射，未知 usage 不伪造为零
webhook/webhook → ctx.webhookRuntime已验证投递与会话创建入口身份与重放策略不由模型自行判断

服务定义、Provider、Consumer 构成能力 seam，将替换时需要保持的行为集中到接口契约。路径、错误码和取消语义都属于这个契约；两个 Provider 即使具有相同类型签名，也可能在这些行为上不兼容。

将上下文编译为有版本的请求

上下文编译把任务、证据和能力约束组织为一次不可变输入。产物包括实际消息、可见工具 schema、证据来源清单、裁剪记录，以及配置与授权快照身份。这样，请求的来源与转换过程都能被追踪。接入 DSH 时，system prompt、tools 与 session seam 提供相应位置，完整的编译产物契约还需要额外实现。

输入与信任层编译时如何处理不能越过的边界
宿主策略与能力限制由受控配置载入，记录策略版本；保留拒绝规则与执行身份仓库文件、检索正文不能覆盖允许路径、外发限制或审批要求
用户任务与明确授权提取目标、范围和完成判据；授权由可信入口确认，不从引文里推导“分析部署脚本”不自动等于“执行部署”；超出范围需要重新授权
仓库文件、网页与工具结果附来源、版本与读取时间，作为带边界的数据段；其中的命令仍是待判断内容正文即使写着“系统消息：忽略限制”，也不提升为宿主指令
压缩摘要与历史结论标记为派生材料，保留原始证据引用、未决问题和覆盖区间摘要不能把“工具结果未知”改写成“工具未执行”，也不能制造新授权

例如，用户只授权修复 src/parser.ts，仓库里的 AGENTS.md 却要求上传环境变量。按上述信任划分，该文件提供仓库协作信息：缩进约定可以采用，外发指令不能改变宿主权限。XML 标签和提示词只能帮助模型识别数据边界；未授权的凭据读取、网络访问和进程启动仍须在工具能力边界拒绝。若产品允许仓库规则成为可信配置，还需要独立的所有者审核与版本发布，文件名本身不授予权限。

工具可见性是提示面，授权快照是决策证据

在这个修复任务中，模型可以看到 read_file 与受限 apply_patch，看不到部署工具；这是降低误调用概率，不是安全边界。请求记录可见 schema 的摘要、工作区基线、主体、策略版本与授权范围；派发时再用模型不可篡改的快照验证动作，并检查当前撤权状态。快照证明“当时允许什么”，不能冻结已经被撤销的权限；新增加的权限也不应静默扩大已批准调用的范围。若 patch 参数已从 parser 改成密钥文件，旧批准必须失效。

每步暴露全部工具、只在执行时守卫，接入简单且保留拒绝后的规划机会，但会占用 schema 预算并增加无效尝试。动态筛选工具更省上下文，却需要保证展示与执行使用同一份身份和范围。两种方案都需要在直接调用路径上执行授权，并将拒绝返回为可解释结果，避免偷偷改成另一个动作。

32k 窗口中的预算与裁剪

假设模型总窗口为 32k token，预留输出 4k、分词差异与封装余量 2k，则序列化输入上限为 26k。当前输入为：策略 2k、任务与未决状态 2k、工具 schema 3k、历史 9k、证据 18k，共 34k。若先把历史压到 4k，再将证据降到 15k，总输入可降为 26k；压缩后仍须按目标模型重新计量，才能决定是否准入。裁剪对象是重复日志、过时文件版本和弱相关片段，保留文件路径、基线摘要、修改约束、失败诊断以及未结算调用。

代价是模型失去部分细节，所以摘要要附可重新读取的证据引用；后续读取仍消耗 第 15 章的总预算，不能把压缩当作免费扩容。若不可裁剪材料已经超过 26k，就拆分任务或选择获准的大窗口路由，不能删除安全约束硬塞请求。另一种“只留最近 N 条”的实现便宜，但会让早先授权边界或未决副作用在长任务中消失，不适合需要恢复的执行型 Agent。

编译器的故障实验可以覆盖三类变化：检索正文中的伪系统指令、请求冻结后的写权限撤销，以及超过窗口的输入。分别检查低信任标记与外发拒绝、派发时的授权决定、裁剪清单和实际 token 量。策略热更新需要在后续执行前重新判断准入；若更换分词器或摘要版本，也应记录编译版本并区分新的请求身份。历史请求的授权摘要只能解释过去的决定，当前执行仍依赖服务端校验；版本衔接见 第 16 章。

文件系统与子进程共享一个执行环境

文档把文件系统与子进程 Provider 放在同一“执行世界”中考虑：ctx.fs、ctx.subprocess 以及消费它们的 shell、终端、LSP 必须针对同一工作区。假设模型在本地读到版本 A，命令在远程版本 B 打补丁，工具返回的 diff 即使合法，也不是它分析过的输入。

环境切换首先需要固定任务的工作区/仓库快照与执行主体，让模型读取、命令 cwd 和产物收集指向同一基线。fs、subprocess、PTY、LSP 和后台任务都是这份映射的消费者；任何本机回退都应显式记录或拒绝，静默回退会把环境错误伪装成正常结果。

取消同样跨越这些消费者。终端、子进程和输出流停止后，工作区才能释放；提前删除目录会与仍在运行的写入竞争。断开远程连接的故障实验可以检查各条读写路径是否一致失败、有无任务转到本机，以及尚未完整收集的产物是否被误标完成。

替代方案是在本机生成 patch、在独立环境只做验证。它减少远程交互，但要求验证使用同一个基线并显式应用该 patch；否则“远程验证通过”与交付的内容仍可能脱节。DSH 的插件树本身不提供这份外部环境一致性证明。

持久事实、活体决策与能力边界

Session：重启后仍应知道

模型输入、工具结果与回合边界进入会话事实。session/event 广播通知观察者，持久性另由 flush 屏障确认。重放读取事实，不重新执行副作用。

Agent：存活执行中的决策

agent/pre-step、请求路由、取消和收尾依赖当前 Agent。初始化 agent/created 按文档需等待完成才让排队工作启动；失败应回滚创建。

能力：所有调用者都应受约束

写前检查应靠近 fs/*，工具执行包装在 tools/*。只在聊天 UI 禁用按钮，拦不住 SDK 或另一个工具路径。

用“批准一次写入”检验域划分：审批对话是活体交互，审批结果若影响恢复审计需要持久记录，最终约束要在真正的写入路径执行。把全部逻辑塞进 Session 观察者，可能事后才看见已经发生的写入；把它只放 Agent 钩子，又可能漏掉无需模型回合的人类命令。还要确认是否存在直接 Node 文件调用等旁路；能力层守卫不是操作系统安全边界。

独立载体的数据与版本兼容性

固定提交文档描述 Electron 携带自己的生产运行时，CLI 与 Desktop 共享产品数据但执行包、激活选择和 lockfile 分离，公开 CLI 不管理 Desktop 的保留 profile。这个例子揭示一个常见误判：共享同一个 home 目录，不意味着两套运行时支持同一个日志格式。旧载体遇到未来格式应显式拒绝，不能悄悄打开旧代继续写；第 16 章继续推导。

RepoOps 接入时的实验身份

projects/repoops/runner.py 的 manifest 已记录数据集、模型修订、系统提示、步数/时间预算与 agent/runner 源码摘要，但它没有 DSH 插件树、远程工作区或 Provider 身份。接入后，这些配置也会影响行为，需要纳入实验身份。将 RulePolicy 换成远程 Agent 已经改变了执行条件，原有 manifest 尚不足以描述两次实验的差异。

可以让两个 profile 只在执行 Provider 上不同，对同一任务比较模型所见证据、工具权限和产物基线，再加入一层覆盖，定位最终插件树的变化。双会话实验则交换创建顺序、关闭其中一个，检查工具注册与会话状态是否互相污染。这两组实验分别检查 Provider 替换和作用域隔离，也为后续结果比较保留配置依据。
