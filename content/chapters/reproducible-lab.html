用合成数据练习评测

这个 Python 实验用合成观测演示配对比较、数据检查和三态裁决。只需 Python 3.10+ 标准库，无需模型 API；结果用于理解统计方法。

十分钟运行

在仓库根目录运行
python labs/eval_lab.py demo --output lab-output
python labs/eval_lab.py compare lab-output/improvement.input.json
python labs/eval_lab.py selection-bias --candidates 30 --seed 17
python -m unittest discover -s tests -v

demo 输出五份输入、五份结果和汇总。每份结果包括逐任务宏平均差、按任务聚类的 bootstrap 区间、保守单侧界、成本、裁决及输入 SHA-256。固定输入和 seed 可重现统计结果。

检查输入与缺失样本

程序要求基线和候选拥有相同的完整 task×run 矩阵；重复 ID、缺失失败、非有限成本、非布尔结果、伪装成功的 timeout/crash 都会报错。reported_score 不参与计算。重复运行保留在任务簇内，不被当成更多独立任务。

candidate_frozen: true 是调用者声明，不是程序证明；confirmation 标签不能证明数据从未被看过。模型、环境与评分器的全局标识是同条件比较的契约，真实运行需要外部 verifier 核实这些标识。输入文件的可修改性也意味着这个工具不能防御同账号下的恶意候选。

接入真实 Agent 观测

  1. 把合成输入替换为独立 runner 的观察。逐题从干净环境运行基线和候选，保存产物与外部断言结果。
  2. 把 cost_units 映射到预先规定的统一成本，例如 token 预算；同时额外保留搜索成本和墙钟时间。
  3. 先用开发集修好 runner，再冻结候选、评分器、任务清单与裁决参数；独立确认集只有一次决定用途。
  4. 将代码快照、模型精确版本、数据/容器 digest、完整轨迹和失败分类写进实验卡。
  5. 需要处理相关任务、连续上线或自适应采样时，升级统计协议；不要直接把本 lab 的独立任务假设带过去。

接入真实模型后的步骤见 P7。合成实验只验证方法与程序，不提供真实模型的性能结论。

三个扩展作业

  1. 把候选数改为 1、10、100，记录开发分数与新数据分数之差。解释为什么 winner's curse 随选择加强。
  2. 注入缺失失败记录、重复成功记录与高分违规，验证门为什么拒绝这些输入/候选；为新失败模式增加回归测试。
  3. 实现按 repo_id 聚类的比较，构造“一个仓库大量近重复题”的例子，和按题聚类对照。
