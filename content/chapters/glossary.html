术语表：定义、运行边界与评测口径

Agent 的运行涉及多个层级：step 与 turn 描述执行过程，outcome 描述任务结果，grader 决定结果是否满足任务契约。它们的边界不同，不能用一个层级的成功替代另一个。本表的 DSH 词条依据上游 docs/glossary.md 的版本快照；框架外概念与项目操作定义分别标注来源，适用范围随来源而定。

step、turn 与 outcome：过程单位和外部结果

设一次用户输入已经准入：模型先要求搜索，再要求读取手册，最后提交建议。按照本表的 DSH 用语，每次模型请求及其引发的工具执行构成一个 step；这次输入排空构成一个 turn，而不是“每调一次工具就是一个 turn”。外层策略是否把它计为 round，由那个策略定义，不能直接拿会话 turn 数代替。

搜索工具返回成功，只说明对应调用按协议结束。若最终建议依据旧版手册，任务仍可能失败。对于数据库修改任务，模型提交“完成”文本之后，还需要查询数据库的最终状态。transcript 记录过程中的动作与观察，outcome 表示外部结果，grader 按任务契约判断是否通过。安全约束还可能要求检查过程：即使最终状态正确，途中越权读取或外传数据也会导致任务不满足约束。

词汇边界对应观测常见混淆
工具调用 / 运行终态请求 ID、状态转换、真实返回值或异常；异步工具还需等待终态。把 accepted / starting 当作激活成功。
transcript / outcome前者记录动作与观察；后者由外部查询或行为断言确认。把“已经修复”的自然语言总结当作 patch 生效。
status / passed正常提交可为 status=ok，但 grader 仍判 passed=false。只用进程退出 0 或工具 ok 汇总成功率。
trial / attempttrial 是预定逻辑测量；重试 attempt 有独立费用与执行身份。重试越多，统计分母和成功样本越多。

seam 与 scope：能力组合和可见范围

DSH 的 seam 指完整可替换能力：Service Definition 约定键与词汇类型，Provider 实现能力，Consumer 使用它。以 shell 为例，替换 Provider 可以改变执行位置；实际隔离程度则取决于挂载的 Provider、工作目录、网络与凭据暴露。接口可替换性与执行隔离是两个独立属性。

scope 描述贡献对哪个 agent 可见，scope key 是不透明身份；它既非文件系统沙箱，也不按名字形成权限继承树。假如子 agent 看不到某个工具，却能通过共享服务读到敏感文件，贡献可见性仍未阻止能力泄漏。能力组合详见工具与能力接缝，访问与执行限制详见安全与护栏。

多次尝试中的求解率与重复可靠性

假设每次尝试独立、成功概率固定为 p=0.8，允许三次中至少一次成功的理想化概率是 1−(1−p)^3=0.992；要求三次全成功则为 p^3=0.512。前者衡量多次机会中找到解的概率，后者衡量连续交付的可靠性。这是独立同分布条件下的手算；直接将单次样本率代入，未必得到无偏估计。实际 pass@k 估计与重复可靠性口径见 04。

如果三次尝试共享同一个错误缓存，独立性假设便不再成立，上面的乘法不再适用。多次尝试还消耗额外成本；99.2% 的三次求解率与另一系统的单次成功率，需要在明确的预算口径下比较。

improver 的可修改性与改进效果

improver 可修改，表示生成候选的配置或代码能够被替换；improver 已改进，则表示替换后在规定条件下取得了更好的改进效果。后一个结论需要在共同的新起点上，与冻结改进器比较，并计入训练和应用的完整成本。01 的解析器实验展示了这一区别，R1 进一步讨论得分增益与训练开销的关系。
